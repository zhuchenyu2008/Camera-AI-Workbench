## 1. 产品体验与实现边界

用户进入工作台后，应能依次回答：现在是否在采集、今天各项活动大约花了多久、某段活动有什么图片依据、哪些时间没有可靠记录、系统是否还在继续分析。

首版必须覆盖：实时预览、事件时间线、分钟记录、小时／日报、原图查看、手动重分析、人工修订、人物／物品档案、摄像头与运行计划、AI配置、用量和状态。单用户、多浏览器会话；适配手机，不做原生App或多人权限管理。

前端只展示后端给出的活动时长、覆盖统计和版本关系。不能在浏览器把事件首尾相减当作实际阅读时长，不能将采集断流、模型失败、身份未知、图片过期统一显示为“暂无数据”。

AI图片输入、模型密钥、RTSP凭据和文件系统路径均由后端管理。前端通过同源HTTPS访问JSON和受鉴权媒体；可以输入凭据，但保存后接口只返回“已配置”，不回显真实值。

## 2. 技术栈与代码组织

### 2.1 实施基线

| 层 | 选择 | 约束 |
| --- | --- | --- |
| 页面 | React＋TypeScript＋Vite | 静态构建产物部署到HTTPS入口；不在VPS常驻开发服务器 |
| 路由 | React Router | 页面可复制链接；刷新详情页由服务器正确回退到入口 |
| 服务端数据 | TanStack Query | 请求缓存、失效、轮询；不将所有服务端资源复制到全局状态 |
| 表单 | React Hook Form＋Zod或等价组合 | 前端即时校验改善体验；服务端校验为最终依据 |
| API类型 | 后端OpenAPI生成TypeScript | operation_id、枚举、错误码以接口文档为准，禁止手写两套同名DTO |
| 播放 | 浏览器原生HLS或按需加载hls.js | 不支持时显式快照降级；所有媒体同源鉴权 |
| 样式 | CSS变量＋有范围的组件样式 | 不依赖大型后台模板堆叠；字体使用本机中文字体 |
| 测试 | Vitest／Testing Library＋Playwright | 分别验证状态逻辑、交互和浏览器完整流程 |

UI状态只在需要共享的最近公共组件提升，不将局部弹窗和输入状态全部放进全局store。[React状态共享](https://react.dev/learn/sharing-state-between-components)

TanStack Query默认的过期／重试策略要显式覆盖，尤其是401、410和写操作；不能默认重试把“证据已过期”变成无限加载。[TanStack Query默认行为](https://tanstack.com/query/latest/docs/framework/react/guides/important-defaults)

### 3.2 URL与筛选规则

- 通用查询参数为 date=YYYY-MM-DD、camera_ids（重复键）、subject_id、activity、analysis_state；具体from／to使用带时区RFC3339。没有提供日期时选择服务器北京时间今天。
- 跨页面沿用日期／人物／机位范围；将筛选写入URL，浏览器返回可恢复。变更筛选清空分页游标与当前事件选择。
- event／minute／summary详情可带 revision。未指定则当前有效版本；指定旧版本时显示“历史版本”，编辑入口需先返回当前版本。
- 报告索引使用 type=day/hour 和 date；小时报表展示同一天各小时条目。页面URL日期与API的local_date映射在同一个适配函数中完成。
- return_to仅接受应用内相对路径；登录重定向不允许外部地址。URL不包含API Key、摄像头密码或完整RTSP URL。
- 删除机位后，历史记录仍按其ID可访问，显示“已删除机位”；名称使用历史快照，不消失成空白。

## 6. 登录、首次配置与今日概览

### 6.1 登录与账户

进入受保护路由先调用 getSession。401才跳转登录，网络故障显示“暂时无法连接工作台”并可重试，不能把所有失败都当作密码失效。登录表单为用户名、密码、提交按钮；支持密码管理器和键盘提交。

login成功后保存CSRF令牌于内存，用户状态进入Query缓存；会话Cookie由浏览器管理，不将令牌写入localStorage。提交中禁用重复登录；INVALID_CREDENTIALS保留用户名、清空密码。logout成功销毁播放器、清空敏感缓存并返回登录。

账户页通过updatePassword提交当前密码和新密码，成功后所有会话失效并返回登录。不要在界面显示“本页仍保持登录”。

### 6.2 首次配置引导

没有摄像头时概览显示四步进度，可随时离开并回来继续：

1. 配置AI服务并测试图像／输出能力。
2. 添加人物／物品参考资料，设置主人物；未设置则只能按机位或未确认人物浏览。
3. 添加摄像头并测试取流，设置运行时段和区域。
4. 查看启用预检，确认启用；等待第一分钟记录。

步骤状态来自后端配置，刷新后不丢失，不靠本地“已点击下一步”判断完成。可先测试视频，AI尚未配置时明确显示采集可用、分析待配置；不将未分析时长记为零活动。

### 6.3 概览

调用 getOverview、listCameras、getPreviewStatus，预览只打开当前选中的一路。主体范围默认主人物，机位范围默认相关全部启用机位；没有主人物时提示选择或建立档案。

内容依次为：日期／范围 → 当前画面与采集状态 → 活动估计与覆盖 → 今日时间线 → 最近10条事件 → 有影响的故障提示。活动展示“约1小时20分钟”，未知、待分析和采集缺口独立显示。

“今日”截至服务器当前时刻；未来计划不加入尚未发生的统计分母。已经生成的历史日报按全天计划范围；今日刷新和历史统计必须由后端范围定义一致处理。

顶部范围改变会同时更新统计和时间线，预览机位选择独立但始终显示名称，不能让用户误以为多路汇总只来自当前播放画面。没有任何事件时展示已采集／待分析进度，不给出虚假的“今天没有学习”。

## 7. 摄像头、运行时段与预览

### 7.1 摄像头列表和添加流程

列表每行显示名称、启用开关、实际采集状态、计划摘要、最近帧时间、分析队列和保留期。手机转换为紧凑信息块，主操作为进入详情；不在每个列表项自动加载视频。

添加表单分为：名称与视频来源 → 测试 → 周计划 → 检测区域与保留期 → 启用。createCamera先保存为enabled=false，取得ID后testCamera异步测试；刷新或中途离开保留服务器草稿。

来源字段：本机visitor地址（固定127.0.0.1，只读）、允许端口、RTSP路径、可选用户名／密码。说明“家庭摄像头通过软路由和frp接入此端口”，提供接入文档链接；表单不要求用户在浏览器连接家庭IP。密码保存后显示“已配置”，输入框为空代表未修改，不发送掩码字符充当新密码。

测试结果显示连接是否成功、编码、尺寸、测试图和错误层级；成功不自动启用。若H.265浏览器不可播放，说明可用快照预览，并建议在摄像头端选择兼容码流，不将这类问题误标为RTSP不可达。

### 7.2 计划编辑

周计划每条包含星期、多选日期、开始时间、结束时间和“结束于次日”开关；全天用明确的“全天”选项生成00:00—次日00:00。页面固定标注北京时间，不使用手机当前时区。

同日结束早于开始但未选择次日时就地报错。重叠条目保存前显示合并预览；空计划意味着不会自动采集，保留临时开始能力。周日跨周一和周计划边界由后端校验结果反馈，不让用户手动计算UTC。

表单打开时固定基线revision，updateCamera携带相应If-Match；提交前发现服务器版本变化须先比对，不能仅换成最新revision就覆盖他人的修改。来源、启用、保留期变化需previewCameraUpdate，展示将重连、将到期图片数、空间预计和ROI复查要求；普通名称变化无需全屏确认。

### 7.3 开始、停止和停用

| 操作 | 用户看见的含义 | 对应接口 |
| --- | --- | --- |
| 临时开始 | 在指定结束时间前覆盖周计划；只对已启用机位可用 | startCamera |
| 临时停止 | 到指定时间前暂停；不是永久停用 | stopCamera |
| 恢复计划 | 清除临时覆盖，立即依周计划判断 | resumeCameraSchedule |
| 停用 | 关闭机位，之后不再因计划自动开始 | updateCamera |
| 删除 | 停止并移除配置入口；历史记录保留 | deleteCamera |

临时操作结束时间默认下一个计划边界，无边界则1小时，最长24小时；确认面板显示具体北京时间和到期后行为。收到202显示“请求已提交，正在开始／停止”，等applied_revision达到control_revision再展示实际状态。失败不把开关强行停留在成功位置。

删除前展示机位名称和“历史文字记录保留，现存图片按原规则到期”，确认后等待任务结果；历史记录入口仍可访问。删除不是“清除全部历史”，首版不添加未经设计的数据清空按钮。

### 7.4 ROI区域编辑器

使用最近一张有效图或主动测试图作底图，显示真实方向与尺寸。提供矩形／多边形包含区、排除区，最多各8个，多边形3～32个点；默认包含全图。保留“还原全画面”按钮，排除区使用斜纹而不是实心盖住内容。

鼠标绘制、拖点、删除区域；手机提供放大后点选顶点，双指缩放与单指拖点区分。点击图像外留白不能生成点，最后提交归一化坐标0～1。

坐标转换必须基于 object-fit:contain 后的实际图像显示矩形：先减容器位置和上下／左右留白，再除显示图像宽高；不能直接用容器宽高归一化。旋转后的自然图像尺寸为基准，缩放或切屏不改变已存坐标。

无有效包含面积、越界或自交多边形就地提示，服务端仍做最终校验。源尺寸／方向变化时显示“需要复查检测区域”，用户可确认重绘；不能无声把原区域套到旋转画面。

### 7.5 预览播放器生命周期

先getPreviewStatus获取mode和同源媒体URL。mode=hls时，若浏览器原生支持HLS使用video.src，否则在支持MSE时按需加载hls.js；不支持则采用snapshot并清楚标注“每秒快照”。hls.js依赖浏览器媒体能力，不能承诺所有浏览器都能播放相同编码。[hls.js支持说明](https://github.com/video-dev/hls.js)

- video使用playsInline、muted和controls；无音频功能。自动播放被浏览器拒绝时显示播放按钮，不当作采集故障。
- 切换机位、离开页面或退出登录时销毁hls实例、abort请求、清理定时器和object URL；不得同时留下多个播放器。
- 页面隐藏时暂停媒体拉取；返回可见先刷新状态再恢复当前会话。预览页面只订阅选中一路，列表缩略图不创建播放器。
- HLS错误最多做2次本地恢复，然后重取PreviewDto。会话改变重新初始化；片段404按旧会话处理；401先检查会话，不无限重连。
- 原生video错误不一定暴露HTTP状态，需调用getSession／getPreviewStatus区分会话失效、断流和编码不支持，不能猜测用户密码错误。
- snapshot模式每秒最多请求一次，上一请求未完成不发下一次；仅可见且处于预览页时轮询。显示X-Captured-At对应时间，超过stale_after_ms标“画面已停止更新”。
- 无计划运行／已停用时显示状态和临时开始入口；打开页面本身不启动采集。历史最后一帧如需显示，必须明确标“最后画面”与时间，不能伪装实时。

手机带宽不足时允许手动切换快照模式；这是显示方式变化，不改变后端每秒保存与分析策略。HLS约12～30秒目标延迟需在预览旁说明，不能用“实时”暗示毫秒级同步。

## 8. 事件时间线与人工修订

### 8.1 时间线页面

顶部为日期、人物、机位和活动筛选；主体为覆盖条、可缩放时间线、事件列表。调用getTimeline获得时间桶，listEvents获得真实事件；两者使用同一范围、scope和投影版本。时间线不是只展示“每个桶最多的类别”，短活动必须仍能从列表进入。

时间桶可为60、300、900秒，单次不超过24小时／1440桶。默认一天采用300秒，放大到4小时内用60秒；移动端默认展示最近可见时间范围并提供“全天”按钮。缩放／平移以明确的开始结束时间为准，不能无限请求历史。

时间线中的采集缺口使用斜纹、已采集未分析使用浅点纹、无法判断用灰色、活动使用类别色。每一段有可读标题、起止时间和时长；鼠标悬浮或手机点按显示详情。短事件可扩大点击热区到最小触摸尺寸，但视觉时间比例及数值不改变。

时间线下方事件列表是等价可访问入口，默认最新在前、分页50条，最多一次100条。显示：活动、人物、起止时间、估计时长、机位、原图状态和是否人工修订；筛选未知人物时也能看到无法归入“我”的片段。

浏览器前进／后退恢复范围和滚动位置；打开详情桌面可用侧栏抽屉，手机全屏页面，两种方式共享/events/:eventId深链接。直接刷新详情不依赖之前已加载列表。

### 8.2 事件详情

详情使用getEvent，展示顺序：活动与人物 → 当前／历史版本 → 跨度与有效时长 → 片段／中断 → 可观察描述 → 证据样本 → 来源分钟 → 修订记录。

例：“20:00—20:20，阅读约19分40秒，中间20秒无法判断”。不能仅用标题“阅读20分钟”掩盖缺口。身份possible时显示“可能为某人，未计入该人物确定时长”，而不是直接换成已识别人名。

证据样本最多先取3张；点击进入完整分钟证据页。旧事件被拆分／合并时，保留旧版本内容并展示replacement_event_ids对应的新事件链接；用户可明确切换当前事件。

操作包括“用原图重新分析”“人工修订”“查看来源分钟”。原图不可用时第一项禁用并显示原因，另外提供“按现有记录重新汇总”入口；不在点击后才告诉用户无图可用。

### 8.3 人工修订流程

1. 读取当前有效事件及revision，打开修订面板，展示原结果和来源范围。
2. 可改主体、主活动、允许标签、开始结束边界；可将事件拆成多个有序区间。提供每段时长预览，预览只是编辑辅助，提交后的权威时长由后端返回。
3. 保留采集缺口和计划外区域不可选择；不能将“没有采到画面”改成已由图片证实的阅读。若用户认为发生了活动，可在修订原因说明，首版不引入独立的无证据手工计时账本。
4. 输入1～500字修订原因，展示“会更新相关分钟视图、事件和汇总”。提交updateEvent，附If-Match、Idempotency-Key和base_source_revision。
5. 成功显示人工修订标记和重汇总任务；旧版可查看。412时保留草稿并展示服务器最新版本，用户选择重新核对后提交，不能自动合并不同边界。

重新运行AI不会自动撤销有效人工修订。页面若展示新的AI候选结果，必须与当前人工有效结果区分，不能在后台任务结束后把用户修订悄悄替换。

## 9. 分钟记录、证据与原图

### 9.1 分钟列表

调用listMinutes，范围最多24小时；更长日期选择引导按天切换。列为时间、摄像头、主要观察、分析状态、分析方式、证据状态、操作。手机每条为时间＋一行描述＋状态，不把桌面大表格缩成不可点的小字。

筛选包括机位、日期、analysis_state。稀疏、逐秒、混合显示在分析方式中，文字说明“本分钟依据4个采样点”或“本分钟有58个实际秒槽”，不能仅写“高精度”暗示没有不确定性。

列表只加载后端有界摘要，不自动拉原图。pending／running行显示任务进度入口；完成后保留当前列表位置更新行内容，不因轮询强制跳回第一页。

### 9.2 分钟详情

调用getMinute与listMinuteEvidence，包含分钟起止、采集覆盖、结果版本、活动片段、模型观察、参考集版本、证据序列和关联事件。显示“采集到60/60秒，分析依据4张”时，应同时说明这是稀疏分析，不能把采集图数当已送模型图数。

每秒证据网格按时间排序，最多60个秒槽，初始加载元数据，图片懒加载。状态分别为可查看、已过期、提前回收、文件缺失、未采到、计划外；它们由后端MinuteEvidenceSlotDto返回，前端不从序号猜测缺失图片。

一分钟跨运行边界时，计划外秒槽置灰并标注，不计入“缺图”。秒槽存在但模型尚未读取的图可正常查看，同时该分钟可能仍是pending；证据可用性与分析状态分栏表达。

### 9.3 原图查看器

打开图片显示采集北京时间、机位、保存尺寸、证据ID和到期时间。这里“原图”指实际保存的完整JPEG，默认最长边1280，不是摄像头无损原始码流。查看器支持缩放、拖动、前后图、键盘左右键／Esc和手机手势。

最多预取前后各1张，离开释放object URL和请求；不预加载全天图像。通过同源getEvidence读取，需要处理JSON错误与二进制成功，不将错误响应当成坏JPEG一直重试。

到期倒计时以服务端meta.server_time和本机单调经过时间估计，服务端判定最终有效。到期或收到410时立即移除当前图片URL和内存缓存，显示时间、原有文字说明和过期原因；仍可查看文字来源。设置TTL变化后失效所有受影响证据缓存并重新查询。

网页不注册会缓存图片的Service Worker，不将图像Base64存入localStorage／IndexedDB；已到期图片不得从Query缓存再次展示。不能承诺撤回用户此前在浏览器外主动保存的副本。

有“保存为参考图”明确操作，需选择人物／物品、名称、裁剪和长期保存确认；调用promoteReference，keep_as_reference=true。说明成功后该独立参考图不受现场图一小时期限影响。过期图不能使用此操作，成功后不修改原现场图的expires_at。

## 10. 手动分析、异步任务与失败恢复

### 10.1 两类明确操作

| 操作名称 | 输入 | 能改变什么 |
| --- | --- | --- |
| 用原图重新分析 | 尚有效的现场图＋当前适用参考资料 | 重新识别可观察活动并创建分钟／事件新版本 |
| 按现有记录重新汇总 | 已保存记录与统计＋当前参考资料 | 生成新汇总文字；不会重新识别已经过期的现场画面 |

入口根据证据可用性提供，文字汇总不应使用笼统“重分析”按钮让用户误以为旧照片还存在。原图模式首版最多单路60分钟；文字模式单次最多一天，可多路。

### 10.2 原图分析的预检与提交

选择范围／机位后调用previewAnalysis，显示可用图片数、覆盖范围、缺失范围、最早到期时间、参考图数量和预计批次。默认allow_partial=false；有缺失时明确选择“只分析仍有原图的部分”才改为true，列表列出未覆盖时间。

preview_token有效30秒。确认按钮点下时若已过期则重新预检，且影响发生变化时需重新展示，不自动提交变化后的范围。预检不保证锁住图片；创建时返回PREVIEW_STALE／REFERENCE_SET_CHANGED则刷新预检。

使用createAnalysisJob提交；同一次意图生成一个Idempotency-Key，网络中断重试仍使用原key和原body。用户修改范围则创建新意图、新key。收到202后在面板显示任务ID和进度，旧记录继续可读。

### 10.3 任务进度与取消

JobProgress读取getJob。显示queued的原因，例如等待服务恢复、等待前置记录、重试将在HH:mm进行；running显示阶段和已成功批次／总批次；total_units=null时只显示阶段，不显示“99%”等待模型。

partial展示成功与缺失范围；failed／expired展示安全错误和是否能再次预检；succeeded提供结果链接并刷新相关资源。取消任务使用cancelJob，先显示“正在请求取消”；已发出的调用可能仍计入用量，取消不是撤销账单。

任务关闭面板仍在服务端运行；状态页可重新找到。前端刷新或手机切换应用不会丢失任务，也不会重复创建。任务完成后只刷新相关数据，不强行跳页打断用户正在编辑的内容。

## 11. 小时汇总与日报

### 11.1 报告索引和详情

报告索引提供日期切换、人物／机位范围、日报和按小时列表。调用listSummaries；没有该范围既有报表时，显示确定性统计与“按现有记录生成”入口，不伪造AI已写好总结。

详情getSummary的内容顺序为：日期范围 → 版本／完整性 → 主要活动与时长 → 覆盖说明 → AI总结 → 事件引用 → 小时明细／来源分钟。活动采用简洁横向条形图，并提供同值列表；unknown、未分析和gap不纳入某种活动的时长。

报表明确区分：

- “暂定版”：部分分钟仍待分析，将在来源更新后重算。
- “已完成，有缺口”：下级已终态，但有断流或未分析的时间，不再假装完整覆盖。
- “来源已更新”：当前文字来自旧版本，新汇总在排队；旧版仍可读。
- “文字生成失败”：确定性统计仍可查看，提供重新汇总，不把所有数值抹为空。

主标题使用“阅读约…”等估计表达。小时明细跨日分割按北京时间，不能因手机系统时区改变而把23:50事件移动到另一日报。

### 11.2 来源和版本

引用渲染为服务端提供的资源ID／版本对应的应用内链接，不将模型输出的任意URL当作可点击可信来源。点击打开来源事件／分钟，返回报告时恢复当前位置。

版本切换显示生成时间、来源是否当前、参考集版本和是否人工修订影响；旧版本只读。regenerateSummary附summary_id、source_revision、reference_policy=current，提交后保留旧版直到新版本可用。

参考图删除导致无法按旧资料重现时，显示“本次使用当前参考资料”，不能声称复现了历史完全相同的模型输入。记录文字中的历史名称可保留，已删除参考图不再显示。

## 12. 人物、物品与参考图

### 12.1 档案列表和详情

listEntities按person／object筛选。每项显示名称、启用状态、适用机位、参考图数量和是否主人物。详情通过getEntity加载，名称必填1～64字，描述最多1000字；描述用于识别说明，不接受不相关的模型操作指令。

camera_ids为空表示所有机位，界面必须显示“所有机位”，不能显示空白并让用户误以为未分配。主人物只能有一个，切换时明确更新默认统计范围；旧记录保留原人物ID和名称快照。

上传单张JPEG／PNG／WebP，≤8 MiB且≤1600万像素；前端做快速检查，后端解码检查为准。显示裁剪预览与名称，提交uploadReference；输入方向与服务端归一化方向一致。手机支持系统相册选择，但不要求浏览器额外申请摄像头权限。

每张参考图可启用／停用、改名、换图、删除。修改使用对应revision；换图创建新的asset_version，不覆盖历史版本标识。删除会撤销旧任务后续读取该资产，历史记录只保留名称和版本信息。

### 12.2 参考容量和每次附图的可见性

页面说明：视觉分析、小时和日报每次都会附当前适用的全部已启用参考图及名称。跨机位汇总使用相关参考集并集；重复适用的同一asset_version只算一份。

启用操作超出图数／字节容量时，显示哪个机位或汇总范围超限、参考图总数、模型可用空间；不能在前端自动停用其他照片。用户可以自行停用不必要照片、选择更大容量服务，或将新照片保存为未启用资料。

新增档案默认作为草稿，上传和配置完成后再启用；没有参考图的主人物不得显示为“已具备身份识别”。删除主人物时需明确改为未指定并刷新默认筛选，不能自动将另一人物当作“我”。

## 13. AI与分析设置

### 13.1 AI服务

通过listProviders展示服务名称、API前缀、模型、密钥已配置状态、能力测试时间和当前用途。配置字段包括名称、base_url、模型、API Key、请求超时、现场图／总图上限、请求体上限、输出token上限及兼容格式。

密钥框留空表示保持原值；“清除密钥”是单独操作。测试调用testProvider并通过getJob展示结果，不能在浏览器直接向模型URL发请求。测试使用无隐私图，不会把当前摄像头画面偷偷用作连接测试。

视觉服务和汇总服务分别选择；汇总服务也必须支持图片，因为每次汇总要附参考图。变更地址／模型／容量后旧测试失效，界面提示重新测试；服务尚未验证时不能显示“可用”。

高级兼容选项收在展开区，采用后端枚举：json_schema／json_object／prompt_json，以及测试通过的token参数。默认不在普通记录页暴露这些实现字段。

### 13.2 分析与保存设置

页面分为图片保存、分析频率与变化检测、事件合并、汇总计划、资源限制。默认值与有效范围全部来自SettingsDto，前端不维护第二套默认配置；每项有简短说明与恢复默认操作，恢复后仍需用户保存。

保存前字段校验后调用previewSettings，展示生效范围：会有多少现存图片立即过期、预计空间、受影响机位、参考图是否超限、是否会重建事件／报表。缩短TTL的明确按钮文案为“保存并使这些图片到期”，普通参数保存用“保存设置”。

图片TTL的最小值受提交周期和重试时间共同约束，默认参数下至少23分钟。用户想更短时给出后端field_errors和所需最小值，不自动减少重试次数。默认仍为60分钟。

全局与单服务同时设置图数／超时时，以effective_limits显示实际值，例如“有效总图上限24张，受当前模型配置限制”。不能只展示全局32张导致用户误判。

设置保存成功后使相关查询失效，显示后台应用进度；发生412保留草稿，发生PREVIEW_STALE重新预检。capture_fps=1、Asia/Shanghai、无通知和无预算封顶在首版为固定说明，不做能点击却没有功能的开关。

## 14. 设备状态与用量

状态页getStatus分为采集、分析队列、存储、模型服务和应用进程。页面直接说明影响，例如“视频断流，20:10之后尚未采到画面”“图片仍在保存，AI服务鉴权失败”“保留期设为60分钟，目前只剩38分钟可用原图”。

采集区域展示每路最近帧、过去5分钟覆盖率、重连、运行时段／临时覆盖。只展示后端实际观测的链路信息；应用无法直接检测家庭路由器时显示“未独立检测”，不能画一条全绿的假网络拓扑。

任务区域listJobs按状态／类型筛选，展示最老图像任务、即将到期任务、失败原因、重试时间和取消入口。详细phase等诊断信息在展开后显示；普通概览只保留用户需要处理的故障。

存储展示准确bytes换算值、各项占用、配额、最早仍可用原图、清理时间和提前回收数量。磁盘保护暂停区别于用户停止，并链接对应设置；不提供随意清空数据库的危险快捷键。

用量页getUsage支持日期、服务和用途分组，显示实际调用次数、成功／失败／未知用量请求、现场图和参考图数量、输入／输出token及可用费用估算。服务未返回token或价格时显示“未知／未配置”，不是0；金额注明币种和估算来源，不设预算拦截。

错误可复制request_id／job_id与脱敏描述，方便排障。复制内容不含密钥、RTSP密码、图片Base64或服务器完整文件路径。

## 15. 数据流、缓存与接口映射

### 15.1 状态归属

| 状态 | 唯一归属 | 生命周期 |
| --- | --- | --- |
| 日期、人物、机位、筛选、当前版本 | URL／路由 | 可复制、可返回恢复 |
| 摄像头、记录、报告、任务、统计 | TanStack Query | 服务器版本为准，按资源失效 |
| 当前表单、裁剪、多边形编辑、确认面板 | 页面局部状态 | 未提交时离开提醒；敏感值不持久化 |
| 会话用户与CSRF | 受控会话上下文＋Query | 登录后建立、退出／401清除 |
| 播放器、图片object URL、请求AbortController | 组件生命周期引用 | 卸载、隐藏或退出时清理 |

Query key包含资源名、规范化后的camera_ids集合、subject_id、from／to、筛选、revision和cursor；集合排序去重，防止同一范围顺序不同生成多份缓存。禁止用“当前日期”一个key装入多个机位数据。

GET默认只对网络错误和明确可重试的5xx最多重试2次，指数退避并遵守Retry-After。401／403／404／410／412／422不自动重试；所有写操作默认不自动重发。需要重试已提交写请求时使用原幂等key和原请求内容。

不对活动时长、事件修订、摄像头实际状态做乐观成功更新。表单可显示提交中的意图，但有效数据以返回revision和后续查询为准。用户正在编辑的草稿不会被后台轮询覆盖。

### 15.2 轮询预算

| 当前可见内容 | 建议周期 | 停止条件 |
| --- | --- | --- |
| 摄像头／状态摘要 | 5秒 | 页面隐藏或离开该页 |
| 今日概览、时间线、分钟列表 | 30秒 | 历史稳定范围可停止；页面隐藏时暂停 |
| 暂定／过时报表 | 60秒 | 当前版本已完成且无待处理变化 |
| 活跃任务详情 | 前30秒每2秒，之后每5秒 | 任务终态、关闭进度面板或页面隐藏 |
| 快照预览 | 1秒，最多一个未完成请求 | 隐藏、离页、切机位、停止或失去会话 |
| 参考图、已完成历史详情 | 无固定轮询 | 显式操作或相关版本失效才刷新 |

同一key复用查询，父子组件不能各自设置一套同类计时器。切回可见时先做一次刷新，避免补发后台漏掉的所有轮询。单次请求超时由统一客户端管理；不用setInterval堆积未完成请求。

成功修改后的失效范围：摄像头配置→camera/status/overview；事件修订→event/minute/timeline/overview/summary；参考变化→entity/reference/provider-capacity/settings；分析完成→本run涉及的minutes/events/timeline/overview/summaries；TTL变化→camera/settings/evidence/preview/status。失效按影响范围执行，不能每次图片加载都刷新全站。

以下只列operation_id，具体路径、请求字段、If-Match和Idempotency-Key要求以[后端路由目录](04-后端详细设计与接口契约.md#43-路由目录)为准。生成客户端使用这些稳定名称。

| 摄像头管理 | listCameras、getCamera、getPreviewStatus | createCamera、previewCameraUpdate、updateCamera、deleteCamera、testCamera、startCamera、stopCamera、resumeCameraSchedule |
| 播放与快照 | getPreviewMedia、getSnapshot | 无 |
| 时间线与事件 | getTimeline、listEvents、getEvent | updateEvent |

### 15.4 幂等、版本与时间

统一API客户端负责credentials=same-origin、X-CSRF-Token、X-Request-ID关联、错误解包。修改既有资源时If-Match格式为`"rev-N"`；K类操作的Idempotency-Key使用随机UUID，每个用户意图仅生成一次。不能每次render或自动重试重生成key。

前端日期显示统一通过time工具，显式指定Asia/Shanghai，不使用无timeZone选项的toLocaleString。日范围由后端或统一工具生成，例如2026-10-17对应UTC的前一日16:00至本日16:00；输入`datetime-local`必须按北京时间解释后再序列化，不能按手机所在时区自动转换。

时间差不使用页面当前渲染时刻去修改源记录；“5分钟前”“还剩10分钟”等相对时间只是显示。页面顶部可显示“北京时间”，工具提示可提供精确到秒时间；时长小于一分钟用秒，统计大于一分钟用分钟，原始duration_ms仍完整保留。

## 16. 错误、并发与安全渲染

| 情况 | 交互规则 |
| --- | --- |
| 401且不是登录提交 | 停止播放器和轮询，清空敏感数据，跳转登录并保留安全return_to |
| 403 CSRF_INVALID | 刷新会话状态，保留非敏感草稿；提示用户再次提交，不自动重复写操作 |
| 404记录不存在 | 显示资源不存在和返回列表；有replacement_event_ids时按历史入口逻辑处理 |
| 409预检／参考集变化 | 重做预检，展示新的影响，不继续使用旧token |
| 410图片／参考资产不可用 | 终止图片加载与重试，显示可读元数据和原因 |
| 412版本冲突 | 保留用户输入，展示服务器新版与差异，重新核对后提交 |
| 413／415上传错误 | 错误定位到文件，保留其他表单字段 |
| 422字段错误 | field_errors.path映射表单，并聚焦第一项；无法定位的错误显示在表单顶部 |
| 429 | 显示可再次操作时间；不每秒弹一次提示；原请求意图保持可恢复 |
| 503／网络中断 | 保留已有页面并标过时；GET受限重试，写请求提示结果未确认并使用原key核对／重试 |

不能将服务端message直接当HTML渲染；模型输出只渲染文本或经允许列表过滤的Markdown，禁止脚本、iframe和事件属性。外部链接需显式外链样式，引用优先使用已验证应用内资源。

错误提示包含安全中文说明和可复制request_id，开发堆栈不出现在普通界面。密码与API Key在失败重试后可留在当前输入组件直到用户离开，但不进日志、埋点、URL或持久缓存；退出和会话失效清空。

## 17. 手机、无障碍与性能

### 17.1 手机完整流程

- 最小验收宽度360px，横竖屏切换不丢表单或ROI坐标；底部导航与表单操作避开安全区和软键盘。
- 触摸主操作至少44×44px，危险操作留出间距；桌面hover功能提供点按替代，不能靠双击或右键才能查看原图。
- 详情和复杂表单在手机全屏呈现；日期、摄像头筛选可折叠，但当前范围始终可见。
- 时间线保留手势平移，也提供“前一段／后一段”和事件列表，避免只有精细拖拽才能使用。
- 视频／图片保留宽高比；表格转纵向信息，不仅缩小字号。用量多指标允许明确标注的局部横向表格，页面本身不溢出。

### 17.2 可访问性

所有输入有label，错误用aria-describedby关联；弹窗焦点限制在内部，关闭后回到触发按钮。键盘可完成登录、选择日期、事件查看、证据翻页、重分析确认和设置保存。

状态用颜色＋文字／图案共同表达；时间线为每个事件提供文本列表。aria-live只播报任务完成、错误和关键状态变化，不每秒朗读画面时间。支持系统减少动态效果偏好，避免频繁闪烁。

### 17.3 性能约束

首屏JS压缩后目标≤300 KiB，不含按需加载的HLS模块和非首屏管理功能；具体构建产物需实测。播放器、ROI编辑器和长记录详情按路由拆包；不为展示几个统计数字引入大型图表平台。

事件列表默认50条，分钟网格最多60秒槽，图片仅视口附近懒加载；一次详情最多预取前后各1张。分页列表超过可见数量时可虚拟化，但必须保留可访问的文本与定位行为。

在服务器正常和普通移动网络条件下，列表进入目标2秒内可读、筛选点击100ms内有反馈；这是待验证目标，网络等待时须立即有加载反馈。停止预览后不应残留网络流、重复定时器或持续上涨的浏览器内存。
