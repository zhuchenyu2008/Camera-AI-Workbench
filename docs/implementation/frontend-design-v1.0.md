# 前端详细设计文档

- **关联产品**：摄像头 AI 总结工作台
- **版本**：1.0
- **状态**：实现基线
- **目标形态**：单用户、自托管、响应式 Web 工作台
- **运行环境**：现代桌面浏览器优先；移动/窄屏提供可用查看能力
- **后端接口**：REST `/api/v1` + SSE
- **核心原则**：时间轴以第二层为准；第一层用于实时临时状态；证据等级可见；处理延迟不伪装成无活动

---

## 1. 前端目标与边界

前端是摄像头 AI 总结工作台，不是通用监控墙。首屏重点让用户回答四个问题：

1. 摄像头现在是否正常采集？
2. 当前正在识别/整理什么，结果是临时还是最终？
3. 过去一小时/一天到底做了哪些活动，哪些是直接观察、哪些是推断？
4. 某个活动结论可以追溯到哪些照片、分钟观察、AI 任务和用户修改？

前端不承担 RTSP 解码、本地变化检测、AI 调用、密钥保存或最终业务判断。浏览器只通过后端读取经过权限校验的缩略图/原图与结构化记录；不把 AI Key、RTSP 凭据或内部文件路径发给浏览器。

### 1.1 实现技术基线

- UI：React + TypeScript + Vite 单页应用；仅构建静态资源，由 Web/API 容器托管。
- 路由：React Router 或等价路由器；列表筛选和时间范围尽量同步到 URL，支持刷新恢复。
- 服务端状态：TanStack Query（或等价 query cache）；瞬时 UI 状态用轻量 store（例如 Zustand），避免把服务端数据复制进多个 store。
- 表单：React Hook Form + Zod（或同等方案）；后端仍是最终校验方。
- 样式：CSS variables + CSS Modules/分层 CSS；不强制重型 UI 套件，组件需支持键盘和主题令牌。
- 测试：Vitest + Testing Library 做单元/组件测试；Playwright 做浏览器端到端与关键视觉回归。
- API 类型：优先从后端 OpenAPI 生成 TypeScript 类型；`TimelineSegmentVM` 等前端显示模型通过独立 mapper 转换，不直接修改生成类型。

以上为本项目的新实现默认基线。若开发阶段替换库，必须保留路由、状态、校验、类型同步、可访问性及测试能力。

### 1.2 产品语言与显示约定

- UI 中文为默认语言；日期/时间按用户设置的 IANA 时区显示，默认 `Asia/Shanghai`。
- API 时间是 UTC RFC3339；前端不得用浏览器所在时区直接替换用户时区。
- 所有时间区间按左闭右开理解；展示时长使用秒级底层、分钟/小时级友好格式。
- 活动名称显示标准名称；具体情境显示 AI 自由描述；两者不能互相覆盖。
- “未知”表示证据不足，不表示没有活动；“空白/未采集”表示采集缺口；“处理中”表示结果尚未完成。

## 2. 信息架构与路由

建议采用以下路由；不要求每个页面都是独立全屏，详情可用侧栏/抽屉实现，但 URL 必须可复制恢复上下文。

```text
/                         工作台首页
/timeline                 时间轴（可带 camera/from/to/query）
/timeline/:cameraId       某摄像头时间轴
/summary                  小时总结、日报
/usage                    AI 使用量与任务
/settings/cameras         摄像头配置
/settings/ai              AI Provider、层级模型绑定、连接测试
/settings/analysis       抽帧、高精度、窗口和变化阈值
/settings/retention      留存、收藏和磁盘
/settings/activities     标准活动目录与别名
/settings/persons        匿名人物档案
/settings/system         单用户访问、时区、备份/健康信息
```

### 2.1 全局布局

```text
┌─────────────────────────────────────────┐
│ 顶栏：产品名 / 当前日期时间 / 队列 / 用量 / 用户菜单 │
├──────────────┬──────────────────────────┤
│ 侧边栏       │ 页面内容区               │
│ 工作台       │                          │
│ 时间轴       │                          │
│ 总结         │                          │
│ 使用量       │                          │
│ 设置         │                          │
└──────────────┴──────────────────────────┘
```

- 桌面宽度 ≥ 1200px：侧栏固定 232px，内容区支持 2/3 栏。
- 768–1199px：侧栏可折叠，时间轴与详情上下布局。
- <768px：使用底部导航/抽屉，默认只展示一个摄像头和一个活动段详情；不尝试把多路监控卡片缩成不可读小格。
- 内容区最大宽度建议 1600px；时间轴可横向滚动但页面不出现无意义的双重横向滚动。

### 2.2 全局状态

全局 store 只保存 UI/会话/查询上下文，不保存完整帧二进制：

- `session`: 登录态、用户时区、能力/版本。
- `cameras`: 摘要状态、连接状态、最近帧。
- `jobs`: 当前窗口/队列摘要。
- `timelineQuery`: camera、from、to、zoom、筛选。
- `activityCatalog`: 标准活动/别名版本。
- `ui`: toast、确认框、详情抽屉、网络状态。

服务端数据使用 query cache（例如 TanStack Query 或同等机制）管理；SSE 只触发精准失效或局部更新，不通过事件流保存无限历史。

## 3. 视觉设计系统

### 3.1 设计方向

采用“观测工作台”视觉，而不是彩色卡片堆叠：中性深色/浅色背景、强时间轴、细边界、少量语义颜色。大块区域优先承载时间和证据，统计卡片只呈现关键指标。

默认提供浅色和深色两套主题，使用 CSS 变量；系统 `prefers-color-scheme` 作为初始值，用户选择覆盖系统设置。颜色不能单独承担语义，所有状态必须同时配文字/图标/纹理。

### 3.2 颜色令牌（示意）

```css
:root {
  --bg: #f6f7f9;
  --surface: #ffffff;
  --surface-muted: #eef1f4;
  --text: #19212a;
  --text-muted: #657180;
  --border: #d9dee5;
  --accent: #2563eb;
  --success: #16845b;
  --warning: #b7791f;
  --danger: #c2413c;
  --unknown: #7b8490;
  --inferred: #7c5cff;
  --processing: #2389a8;
}
```

活动类别颜色只是辅助：学习蓝、工作青、娱乐橙、生活绿、休息紫、未知灰。活动段仍显示标准名称和证据图例；推断区间使用斜纹/虚线叠加，不只换色。

### 3.3 字体与密度

- 中文 UI 使用系统无衬线字体栈；数字使用等宽或 tabular numerals，保证时间列对齐。
- 正文最小 14px；主要标题 20–28px；时间轴标签最小 12px。
- 默认紧凑但不拥挤：控制台信息密度高，卡片留白优先用于层级，不做无意义大圆角/阴影。

### 3.4 动效

- SSE 更新使用 150–250ms 状态过渡；不闪烁整个时间轴。
- 处理中使用低频脉冲/进度条，不使用持续快速动画。
- `prefers-reduced-motion: reduce` 时取消平移、闪烁和非必要过渡。
- 实时最新帧更新不得导致页面滚动位置跳动；用户查看历史时暂停自动跟随，显示“回到最新”按钮。

## 4. 数据获取、缓存和实时同步

### 4.1 首屏加载顺序

1. 获取会话/版本/时区和基础设置。
2. 并行获取 `/overview`、摄像头列表和默认时间轴区间。
3. 先渲染骨架与摄像头健康状态，再填充活动段/摘要/用量。
4. 建立 SSE 连接；连接成功后发送当前查询上下文只用于客户端过滤，服务端仍按权限推送。
5. SSE 失败时显示离线提示，使用轮询/失效重拉作为有限降级；恢复后做一次全量一致性刷新。

### 4.2 Query key 设计（示例）

```ts
['overview']
['cameras']
['timeline', { cameraId, from, to, filters, includeObservations }]
['segment', segmentId]
['summary', { cameraId, kind, period }]
['jobs', { cameraId, state, cursor }]
['usage', { from, to, layer, provider, cameraId }]
['activityCatalog']
['settings', section]
```

- 时间轴查询结果按区间缓存；缩放或平移采用相邻区间预取，不一次加载整日原始帧。
- 活动段变更事件只使受影响摄像头/时间区间失效；避免刷新整个页面。
- 图片 URL 由 API 返回短时 token/认证路径；缓存策略由后端控制。过期时前端显示证据过期，不反复重试。

### 4.3 SSE 处理

事件字段：`id,event,data`；前端保存 `Last-Event-ID`，重连后发送。收到事件后：

| 事件 | 前端动作 |
|---|---|
| `camera.status` | 更新对应摄像头状态；必要时刷新 health |
| `frame.latest` | 更新最近帧元数据/缩略图，历史查看不自动跳转 |
| `job.updated` | 更新任务 badge；对相应时间范围做轻量失效 |
| `timeline.updated` | 失效受影响 timeline/segment query；保留用户当前缩放 |
| `summary.updated` | 更新摘要状态并显示新版本提示 |
| `storage.updated` | 更新磁盘卡片/留存清理状态 |

SSE 断开超过 5 秒显示“实时连接已断开，数据可能延迟”；超过 30 秒采用退避轮询；恢复后隐藏提示并刷新当前视图。若事件版本落后，以 HTTP 查询结果为准。

### 4.4 错误、空态和陈旧态

所有 API 错误显示用户可理解的中文和 request ID；不展示堆栈、原始供应商响应或路径。

- 首次加载：骨架屏，不显示“暂无活动”。
- 无数据：明确是“所选时间没有已生成记录”还是“尚未采集”。
- AI 处理中：时间轴显示处理中纹理，并说明层级和预计状态，不填充活动。
- AI 失败：显示“分析失败，可重试”，保留已知第一层/第二层旧版本。
- 证据过期：活动仍可看，但证据区域显示“照片已按留存策略清理”。
- 网络离线：保留已缓存数据，禁止让用户误以为实时状态仍更新。

## 5. 首页工作台 `/`

### 5.1 信息层级

首页按以下顺序：

1. 顶栏实时连接/系统状态；
2. 摄像头健康与当前状态；
3. 当前时间轴/实时活动；
4. 最近一小时摘要与关键统计；
5. AI 队列和使用量；
6. 异常与需要处理事项。

### 5.2 摄像头卡片

每张卡片包含：

- 名称、在线/离线/重连中；
- 最近成功帧时间、距现在多久；
- 当前分析模式：普通/高精度；
- 当前状态：采集中、第一层识别中、第二层整理中、已完成、失败；
- 临时活动：第一层候选或本地稳定延续，并标注来源；
- 最终活动：最近第二层活动段；
- 最近 5 分钟/小时入口；
- 采集缺口和磁盘占用摘要。

状态示例：

```text
在线 · 最近帧 3 秒前
第一层 AI 识别中 · 已提交 8 张图
临时判断：疑似写作业
```

或：

```text
在线 · 画面稳定
沿用上一状态 · 本地判断
最终活动：写作业
```

卡片操作：查看时间轴、暂停/恢复采集、重新连接、打开摄像头设置。停止采集需要确认，并明确停止不等于删除历史。

### 5.3 实时活动条

首页显示当前本地时刻对应的窗口：

- 上层：活动段颜色/纹理；
- 中层：标准活动名称；
- 下层：AI 层级和状态；
- 右侧：更新时间、置信度摘要、证据入口。

如果第二层尚未完成，优先显示：

```text
第一层 AI 识别中
疑似：写作业
```

第二层完成后替换为：

```text
写作业
第二层已整理 · 证据覆盖 68%
```

替换应保留“查看处理过程”入口，而不是突然改变文字让用户丢失上下文。

### 5.4 首页摘要

摘要卡提供：本小时主要活动、已识别时长、未知时长、推断时长、活动切换次数。点击进入完整小时总结。若摘要 stale，显示“活动记录已修改，摘要待更新”。

## 6. 时间轴 `/timeline`

时间轴是产品核心界面。

### 6.1 查询工具栏

- 摄像头下拉/多选；默认全部或上次选择；
- 日期选择器、时间范围；快捷范围：现在、最近 1 小时、今天、昨天、自定义；
- 缩放：小时、30 分钟、5 分钟、活动段；
- 筛选：标准活动、类别、证据等级、未知、处理中、失败、人物簇（匿名）；
- 显示选项：显示第一层临时观察、显示证据点、显示本地稳定延续、显示窗口边界。

查询范围大于 24 小时时默认只加载活动段和总结，不加载所有观察/帧；用户可缩小范围后再展开证据。

### 6.2 时间轴布局

```text
日期/时间标尺
│ 09:00        09:10        09:20        09:30
├────────────────────────────────────────────
│ 摄像头 A  █████ 写作业 ███ 玩手机 ███ 整理桌面
│           └ 直接观察 ┘ ▧ 推断区间
│ 摄像头 B  ···离线···   █ 看书             
├────────────────────────────────────────────
图例：实色直接观察 / 斜纹推断 / 灰色未知 / 虚线处理中
```

每个摄像头一行；同一活动段中有不同 `activity_interval` 时用内嵌纹理表达。摄像头离线/无帧用独立断流带，不占用活动段颜色。

### 6.3 时间轴交互

- 滚轮/按钮缩放；拖拽平移；键盘可用 `+/-` 和方向键（需提供可见提示）。
- 点击活动段打开右侧详情抽屉；双击/Enter 进入编辑模式。
- 点击推断子区间直接定位到缺口前后锚点；点击证据点打开证据查看器。
- 点击处理中窗口打开任务状态，不生成活动编辑表单。
- 用户查看过去区间时不自动滚到最新；顶部显示“回到最新”。
- 相邻段边界显示可选的切换标记；当边界来自推断时显示“约”。

### 6.4 时间轴状态

| 状态 | UI 表达 |
|---|---|
| 第一层临时 | 细边框/斜线，标签“第一层观察” |
| 第二层最终 | 实色主块，标签“已整理” |
| 推断补全 | 主块内斜纹，标签“推断” |
| 未知 | 灰色点阵/灰块，标签“未知” |
| 证据不足 | 黄色边框，提示补证/待复核 |
| 处理中 | 虚线+低频脉冲，标签层级 |
| 失败 | 红色边框+错误图标，可重试 |
| 证据过期 | 正常活动色+灰色相机图标，详情说明照片过期 |

不能只依赖颜色；图例、文字和 aria-label 同时提供。

## 7. 活动详情抽屉

### 7.1 顶部摘要

- 标准活动名称（如“写作业”）；
- AI 自由描述（如“完成数学作业”）；
- 起止时间、持续时长；
- 类别；
- 状态/锁定；
- 置信度及证据覆盖率；
- “用户修改”“推断补全”“证据已过期”等徽章。

### 7.2 证据分栏

按时间顺序展示：

1. 直接观察帧；
2. 推断缺口的前/后锚点；
3. 遮挡/断流/稳定信号；
4. 第一层对应分钟观察卡；
5. 第二层判断说明和工具调用概要。

证据卡显示捕获时间、摄像头、来源层级、图片加载状态。不要在前端显示完整 prompt 或敏感 provider 响应；显示“使用了 2 次证据查询工具”这类安全摘要即可。

证据图片加载：缩略图先加载，点击后在模态查看器打开；查看器支持上一张/下一张、时间、放大、关闭、键盘 Esc。图片 404/410 时显示保留期已过，不无限重试。

### 7.3 编辑模式

编辑字段：

- 开始/结束时间；
- 标准活动下拉；
- 类别（随标准活动默认值，可手动覆盖）；
- AI 具体描述；
- 锁定；
- 编辑原因。

保存前显示影响说明：

```text
保存后：
- 此活动段将保存为用户修正版；
- 相关小时总结/日报会标记为待更新；
- 已锁定区间不会被自动分析覆盖。
```

使用 `expected_version` 保存。409 冲突显示服务器新版本、用户当前编辑内容和“重新加载/保留我的修改”选择，不静默覆盖。

### 7.4 拆分与合并

- 拆分：用户选择时间点；前后活动可复制标准名称但必须分别保存，证据区间重新计算并显示待处理状态。
- 合并：只允许相同摄像头、时间相邻/重叠可解释、且用户确认；若标准活动不同，要求选择保留哪一个或标为未知。
- 操作后时间轴局部刷新，相关总结失效；显示撤销入口（在本次会话可用）或通过审计历史恢复。

## 8. 总结页 `/summary`

### 8.1 页面结构

- 时间范围切换：当前小时、选择小时、今天、某日；
- 摄像头切换：单路/总览；多路总览必须明确“按摄像头统计”，不能无标注相加；
- 总结正文；
- 活动统计表/条形图；
- 活动切换与连续时段；
- 未知/推断/采集缺口；
- 来源活动段列表。

### 8.2 总结状态

```text
已生成
正在更新（活动记录有修改）
数据不完整（存在采集或 L2 缺口）
等待第二层结果
生成失败，可重试
```

总结卡必须把“未知/无数据”与“休息”分开。摘要正文中若使用“主要在……”，旁边提供“查看依据”链接至活动段。

### 8.3 统计呈现

- 标准活动按 canonical ID 汇总，AI 自由描述作为细节；
- 时长用 `小时 分钟`，短于 1 分钟显示秒；
- 推断时长和直接观察时长分开展示；
- 低置信活动不隐藏，可用筛选查看；
- 不使用饼图承载过多活动，优先排序条形列表和时间分布。

## 9. 使用量与任务页 `/usage`

### 9.1 用量总览

筛选：时间范围、摄像头、AI 层级、Provider、模型、任务状态。指标：

- 请求次数（含重试/不含重试拆分）；
- 发送图片张数/字节；
- 输入/输出/总 Token（缺失时显示未返回）；
- 工具调用次数；
- 平均/分位耗时；
- 估算费用（可得时）；
- 失败、429、超时。

不要把无法取得的费用显示成 0；显示“端点未返回价格，无法估算”。

### 9.2 任务表

列：层级、摄像头、时间范围、状态、模型、图片数、Token、耗时、重试、创建/完成时间。点击进入任务详情：错误安全摘要、输入帧数量（不默认展示全部）、重试记录、工具调用摘要、输出校验结果。

用户可对失败/可恢复任务点击重试；需要图片但证据已过期时按钮禁用并说明原因。

## 10. 设置页面

### 10.1 摄像头设置

字段：名称、RTSP URL、凭据、启用、采集间隔、分辨率/质量、单路留存覆盖、测试连接。RTSP URL 输入框默认隐藏密码部分；保存后显示脱敏。删除/停用分开：停用保留历史；删除需要确认是否仅删配置或连同历史数据一起清理。

连接测试结果分为：

- 可连接且可解码；
- 可连接但无法解码；
- 超时/拒绝；
- 凭据失败；
- 地址不合法；
- 网络策略阻止。

### 10.2 AI 设置

Provider 表格显示：标签、base URL 主机名、已配置模型/层级、图像/tools/JSON/usage 能力、最近测试、启用状态。API Key 使用密码输入和轮换按钮，绝不回显完整值。

模型绑定三行：L1 视觉观察、L2 活动推理、L3 总结；每行选择 Provider、模型、备用端点、超时、最大重试、并发。保存前显示“视觉图片将发送到该端点”的提示。

连接测试分步显示：文本、图像、多图、工具调用/JSON action、usage 字段；某一能力失败不掩盖其他能力状态。

### 10.3 分析设置

- 第一层普通/严格/智能模式；
- 稳定抽样数量、变化关键帧上限；
- 前置缓存、后置观察、最长高精度；
- 5/10 分钟 L2 周期；
- 最大连续性推断缺口；
- 低分辨率检测尺寸、阈值、确认帧数；
- L2 工具轮数和额外帧上限。

每项设置显示简短影响说明，例如“增加高精度帧数会提高图片上传量和处理延迟”。保存后只影响新建任务；现有 AIJob 保留配置快照。

### 10.4 留存和存储

分别设置普通帧、事件帧、收藏覆盖、时间轴、总结、人物匿名特征的保留期。显示当前总空间、图片占用、到期量、清理上次运行结果和“立即清理”。危险操作需要二次确认并列出影响范围。

### 10.5 活动目录

列表列出标准名称、大类、别名、引用次数、启用状态。支持新建、编辑、合并别名、停用；有历史引用时删除改为停用或要求迁移，不破坏旧时间轴。

### 10.6 匿名人物

显示匿名 cluster ID、首次/最近出现、出现次数、置信度。支持关闭人物聚类、合并、停用/删除派生特征；页面明确“不识别真实身份、不区分本人/其他人”。

## 12. 表单、确认和乐观更新

- 表单提交前做客户端基础校验，服务端校验仍是最终依据。
- 摄像头 URL、Provider URL、留存时长、阈值和时间范围均显示格式错误和业务限制。
- 关键写操作使用 loading/disabled 防重复提交，并优先发 `Idempotency-Key`。
- 活动编辑不做无条件乐观写入：可先在时间轴本地预览，保存后等服务器版本返回再提交 query invalidation。
- 停止采集、删除配置/历史、清理原图、切换 Provider、启用严格模式显示影响范围。
- 保存成功后 toast + 局部更新；失败保留用户输入，显示 request ID 和可操作的重试/取消。

## 13. 可访问性

目标 WCAG 2.2 AA 级别的关键路径可用性：

- 所有按钮、图标按钮、时间轴块有可访问名称；图标按钮不得只有无意义 SVG。
- 键盘可完成导航、打开详情、编辑、保存、取消、缩放和证据切换；焦点可见且不被抽屉遮挡。
- 抽屉/模态打开后焦点移入，关闭后返回触发元素；Esc 可关闭非危险模态。
- 时间轴提供表格/列表替代视图：屏幕阅读器能读到摄像头、活动、起止时间、状态和证据等级；不要求用户只靠颜色或图形理解。
- 颜色对比满足 AA；推断纹理同时提供“推断”文本。
- 实时更新使用 `aria-live="polite"`，只播报重要状态变化，不每秒播报帧。
- 动效遵循 reduced motion；图片有说明性 alt，例如“摄像头 A，09:20:05，活动段证据”。
- 表单错误与字段关联，通知不只使用颜色。

## 14. 性能预算

目标以普通无 GPU Linux 服务 + 桌面浏览器为基准；首次加载和交互必须在真实数据量下验证。

- 首屏 HTML/JS 可交互目标 ≤ 3 秒（局域网、空缓存/基线数据）；不可把历史图片打进首屏。
- 首页首屏 API 并行请求目标 ≤ 4 个主要请求，SSE 在首屏可交互后连接。
- 24 小时活动段时间轴只加载结构化活动段，不加载每秒帧；默认响应建议 ≤ 500KB，超出用分页/窗口化。
- 时间轴绘制使用 canvas/SVG/虚拟列表按实际数据量选择；不为每秒帧创建大量 DOM 节点。
- 图片使用缩略图、懒加载、解码尺寸提示；活动详情一次只加载当前段有限证据。
- SSE 事件合并/节流，避免每秒触发全局 React/Vue 树重渲染；最新帧只更新目标卡片。
- 长列表、用量表、任务表采用虚拟滚动或分页；导出在后端生成。
- 浏览器端不做大规模图片差异计算或 AI 处理。

## 15. 前端错误与可观测性

前端日志事件至少包含：页面、动作、request_id、camera_id/segment_id/job_id（如有）、错误 code、网络状态、应用版本；不记录 URL 凭据、API Key、原始 prompt 或图片内容。

监控/诊断：

- API 请求耗时、错误率、取消/重复提交；
- SSE 连接状态、重连次数、最后事件时间；
- 时间轴渲染耗时、当前区间数据量；
- 图片加载错误/过期比例；
- JS 未捕获异常、组件错误边界；
- 关键操作漏斗：打开详情、查看证据、修正活动、重试任务、保存设置。

生产错误上报需支持脱敏/关闭开关；单用户部署默认只写本地安全日志，不强制第三方监控。

## 16. 前端测试方案

### 16.1 单元测试

- UTC 与用户时区显示、DST 边界、时长/左闭右开。

- 未认证、后端 401/403/409/429/5xx、SSE 断开/恢复。
- 键盘/屏幕阅读器关键路径和 reduced motion。

- 中文默认、时区显示、深浅主题、响应式和关键可访问性。
- 加载/空/错误/离线/陈旧状态完整覆盖。

### 17.2 P1 交付

- 匿名人物档案管理。
- 用量 CSV 导出、任务高级筛选。
- 时间轴列表替代视图、键盘快捷键帮助。
- 备份恢复状态页面、更多诊断展开。

### 17.3 前端完成定义

1. 首屏在没有历史帧时仍能清楚表达采集/分析状态，不用空白或错误活动填充。
2. 用户能从首页进入活动时间轴，再从时间轴进入证据和第一层记录。
3. 同一 5 分钟内的两个以上活动在 UI 中能清晰分段，遮挡推断以纹理和文字区分。

7. 关键流程可用键盘完成，时间轴有可读列表替代；颜色不是唯一信息来源。
8. 在目标数据规模下不因每秒帧或 SSE 更新造成明显卡顿。
9. 视觉回归、E2E、错误边界和 API 契约测试通过。

## 18. 前后端联调顺序

1. 先冻结时间、状态、活动段、证据和 Job DTO；前端使用 fixture 开发。
2. 后端先提供 `/overview`、`/timeline`、`/segments/{id}`、`/events` 的读取接口和假数据注入。
3. 完成首页/时间轴/详情的加载、空态、错误态，再接入真实 SSE。
4. 接入活动编辑、版本冲突、拆分/合并和摘要失效。
5. 接入 Provider/分析/留存设置，最后接任务重试和用量细节。
6. 使用固定的 L1/L2/L3 mock 响应跑端到端，再切换到真实 OpenAI-compatible 端点探测。
7. 以验收场景 AT-01～AT-14 逐项联调；每项保留截图/日志/数据库状态证据。

> 本文与后端设计文档共同构成实现基线。前端可以替换框架或组件库，但不能省略时间轴证据等级、第二层多活动段、推断可见性、错误/缺口状态、密钥不下发和版本化编辑等行为要求。
