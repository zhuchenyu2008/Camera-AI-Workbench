# 时间序列视觉分析与多轮取证架构

版本：0.1｜修订日期：2026-10-20｜状态：目标架构，尚未实现

本文定义摄像头 AI 工作台下一阶段的视觉分析方向。它补充并在视觉分析部分优先于[产品 PRD](01-摄像头AI工作台-PRD.md)和[后端详细设计与接口契约](04-后端详细设计与接口契约.md)；采集、鉴权、证据 TTL、数据库安全和任务租约仍以原有文档为准。

## 1. 目标

视觉模型应把按时间排序的多张现场图片理解为一个连续观察窗口，而不是把每张图片或每个自然分钟当成相互独立的分类请求。模型应自行判断：

- 活动是否在窗口内持续；
- 哪些时间点直接看到了活动；
- 哪些时间点需要结合前后证据推断；
- 哪些时间点存在冲突、缺少证据或需要继续取图；
- 活动切换发生在哪个边界范围内。

“人物被挡住”只是模型可能给出的一个解释，不应被后端写成针对某个例子的特殊规则。背影、遮挡、光线变化、局部离开画面、镜头抖动和画面质量下降都由模型在统一的时间序列推理中处理。

系统仍必须诚实区分：模型推断、直接观察、无法判断和实际没有采到画面。推断结果可以用于活动时长，但页面和报表要明确其依据和不确定性。

## 2. 当前实现与差距

当前实现已经具备现场图片、分钟记录、持久任务、结构化输出、证据引用和活动账本，但视觉请求仍有四个限制：

1. 提示词要求每分钟独立返回，模型不能直接对跨分钟窗口作整体判断。
2. `VisualOutput` 以分钟为输出单位，`pack_frames()` 按自然分钟拆批。
3. 当前全局设置默认每个现场请求最多 20 张图片；一分钟 60 张 dense 图片通常会拆成多个模型请求。
4. `normalize()` 包含固定的边缘补全逻辑，后端会替模型决定部分时间区间能否延续。

当前 `AIClient` 只发起一次 Chat Completions 请求并解析最终 JSON，尚未支持工具调用、多轮消息、工具结果回传或中途主动取证。因此本文是目标架构，不能被验收清单当作已完成能力。

## 3. 总体分层

```text
RTSP 采集与证据保存
        ↓
时间窗口构造器
        ↓
下级 AI：对有序图片建立局部时间线
        ↓
上级 AI：读取局部结果，按需调用取证工具
        ↓
上级 AI：输出跨窗口时间线与待解决问题
        ↓
后端证据校验、版本提交和事件投影
        ↓
小时汇总与日报
```

AI 是活动语义和时间连续性的判断者。后端负责：

- 只提供当前任务授权范围内的图片和结构化上下文；
- 校验模型引用的证据确实存在、属于正确摄像头和时间范围；
- 校验输出区间不越过计划、任务窗口和真实采集边界；
- 保存模型原始结果、工具调用审计和可追溯版本；
- 将有效时间段投影到分钟记录、事件和报表。

后端不根据“前后各多少秒”“中间是否有多少张图片”等固定模式自行补活动。

## 4. 时间窗口

### 4.1 窗口内容

每个视觉任务固定一个 `window_start`、`window_end`、摄像头、源版本、参考集版本和图片快照。用户图片按采集时间升序发送，文本元数据至少包含：

- `camera_id`、`session_id`、`evidence_id`；
- `captured_at`、`slot_at`；
- 图片是否仍可读取、是否属于测试图；
- 前一窗口的当前结论和待解决问题（如果有）。

图片只以证据 ID 和时间顺序作为模型输入。参考图明确标注为命名辅助资料，不能证明当前时刻发生过某种活动。

### 4.2 窗口大小

窗口大小由 Provider 实测能力、请求体、图片 TTL、队列年龄和资源压力共同决定，不写死为“一个自然分钟”。可以使用短窗口、重叠窗口和滚动检查点，但这些是上下文管理参数，不是活动语义规则。

初始实验可从 5 分钟窗口和 30 秒重叠开始，实际值必须通过人工标注回放确定。生产配置应同时记录：

- 目标窗口时长；
- 重叠时长；
- 每窗口最多图片数和总字节数；
- 最晚完成时间与图片最早过期时间的安全余量。

对于支持视频输入的 Provider，可以使用短视频窗口；对于仅支持图片的 Provider，使用按时间排序的图片序列。两者都必须输出相同的时间线契约。

## 5. 下级 AI：局部时间线

下级 AI 的任务不是对每个图片单独分类，而是对当前窗口生成一份局部时间线。输出应允许活动跨越自然分钟，并允许同一活动有多个证据状态。

建议的结构如下，字段名可在实现时调整：

```json
{
  "schema_version": "temporal-1",
  "window_start": "2026-10-20T20:00:00+08:00",
  "window_end": "2026-10-20T20:05:00+08:00",
  "segments": [
    {
      "subject_id": null,
      "identity_status": "unknown",
      "activity": "写字",
      "start_at": "2026-10-20T20:00:04+08:00",
      "end_at": "2026-10-20T20:04:58+08:00",
      "certainty": "inferred",
      "evidence_ids": ["ev_001", "ev_020", "ev_240"],
      "boundary_evidence_ids": ["ev_001", "ev_240"],
      "explanation": "前后时间点活动一致，窗口中没有观察到切换证据。"
    }
  ],
  "unresolved_ranges": [],
  "review_requests": []
}
```

`certainty` 只表达模型对该时间段的判断方式：

- `direct`：有直接清晰证据；
- `inferred`：结合时间序列和多个证据推断；
- `uncertain`：存在不足或冲突，不能给出稳定结论。

模型可以在 `explanation` 中说明遮挡、光线、画质、人物进出等原因，但后端不根据这些自然语言关键词分支。明确的“未获取到画面”仍由采集元数据提供，不由模型伪造。

下级 AI 还可以返回 `review_requests`，说明需要上级 AI 查看哪一段、希望核对什么，而不是自行扩大图片输入。

## 6. 上级 AI 与多轮工具调用

### 6.1 上级 AI 的职责

上级 AI 接收：

- 一个或多个下级时间线结果；
- 相邻窗口的重叠区结果；
- 当前窗口的采集覆盖和证据状态；
- 必要的边界图片和参考集版本；
- 之前检查点的结论与未解决问题。

它可以主动决定：

- 哪些边界需要再次查看；
- 是否需要查看两个结论之间的中间图片；
- 是否需要核对人物出现、离开或活动切换；
- 当前结论是否可以提交，还是应保留为不确定。

上级 AI 不直接访问文件系统、数据库、任意 URL 或模型密钥。所有取证都通过工作台提供的受限工具完成。

### 6.2 工具边界

第一版建议只提供三类工具：

```text
get_frame_manifest(from, to, camera_id)
  返回时间范围内可用、过期、缺失的 evidence_id 和时间戳，不返回文件路径。

view_frames(evidence_ids)
  返回已授权的现场图片及其固定元数据；只允许当前任务窗口内的 ID。

get_analysis_context(from, to, camera_id)
  返回下级时间线、当前事件版本、冲突和未解决问题，不新增事实。
```

每次工具调用都由后端执行以下检查：

- 摄像头和时间范围属于当前任务；
- evidence ID 属于该范围且状态仍为可用；
- 图片数量、请求体和工具轮数不超过 Provider 与任务预算；
- 调用没有越过图片 TTL、任务 deadline 或人工权限；
- 每一次请求和返回都写入审计记录，但不保存完整图片请求体。

工具返回后，工作台将结果作为下一轮消息继续交给同一个上级 AI。模型完成后必须返回结构化时间线，不允许以工具调用未结束作为成功结果。

### 6.3 多轮终止条件

一次上级检查在以下情况之一发生时结束：

- 模型明确提交了完整时间线；
- 模型认为现有证据不足，并返回 unresolved 范围；
- 达到工具轮数、图片数、字节数或 deadline；
- Provider 拒绝工具调用或结构化输出。

达到限制时应保存 partial 结果和已查看范围，不能把未查看区间标成 complete。

## 7. 上级 AI 的触发逻辑

上级 AI 不是固定每 5 分钟机械调用，也不是等活动结束后才调用。需要三类触发器：

### 7.1 常规滚动检查

当一个窗口或一批相邻窗口的下级结果齐备后，按滚动检查周期创建上级任务。上级任务读取上次检查点附近的重叠结果，必要时取图，然后提交当前时间线版本。

初始实验可以使用 5 分钟周期，但这只是待回放验证的调度参数。需要单独测量：

- 从证据产生到上级结论的延迟；
- 每小时请求数、图片数和费用；
- 长活动中错误延长和错误切断的比例；
- 在图片 TTL 内完成最终取证的比例。

### 7.2 问题驱动检查

下级 AI 或窗口合并发现以下问题时立即或尽快创建上级任务：

- 相邻窗口对活动类别或人物身份冲突；
- 活动边界超出当前证据能支持的范围；
- 模型主动请求更多证据；
- 下级结果出现大范围 `uncertain`；
- 窗口重叠区无法对齐；
- 摄像头重新连接、计划切换或长时间缺帧后恢复。

问题任务要合并去重，避免同一时间段反复启动多个上级 AI。

### 7.3 收尾检查

在以下事件发生时触发一次收尾检查：

- 摄像头停止或离开计划时段；
- 持续窗口不再产生新证据；
- 活动长时间没有新的下级结果；
- 最早相关现场图接近过期；
- 用户查看、导出或手动确认某段历史记录。

收尾检查固定该时间点以前的版本；之后的新图片产生新的滚动窗口，不修改已经提交的历史版本。

## 8. 长时间活动和窗口合并

10～20 分钟活动不应把几百张图片强行放进一次请求，也不应让后端用固定规则连接分钟。推荐使用：

1. 重叠的局部窗口由下级 AI 生成时间线。
2. 上级 AI 查看窗口之间的结论和边界证据。
3. 上级 AI 必要时主动取中间图片或重新查看边界。
4. 上级 AI 输出跨窗口的最终时间段和 unresolved 范围。
5. 后端将最终时间段投影到分钟记录和事件，并保留来源窗口及上级检查版本。

如果上级 AI 也达到上下文限制，可以递归合并：先合并相邻窗口，再合并更大的时间范围。每一级都必须保留来源指纹、证据 ID 和未解决范围，不能只传一段没有来源的自然语言摘要。

真实断流、计划外时间和已过期且无法恢复的证据仍然是硬边界。AI 可以在边界内做推断，但不能凭空跨越这些边界。

## 9. 任务与数据模型变化

在不破坏现有分钟和事件 API 的前提下，新增或扩展以下持久对象：

| 对象 | 作用 |
| --- | --- |
| TemporalWindow | 摄像头、时间范围、图片快照、重叠范围、源版本和 TTL 边界 |
| TemporalRun | 一次下级或上级分析的配置、模型版本、提示词版本和父子关系 |
| TemporalToolCall | 工具名称、参数摘要、返回证据摘要、轮次、状态和错误 |
| TemporalSegment | AI 输出的跨分钟活动段、certainty、证据和边界范围 |
| TemporalCheckpoint | 上级 AI 最近一次已确认时间线、未解决范围和下一次触发原因 |

现有 `minute_records`、`activity_spans` 和事件投影可以作为兼容读模型。新分析结果先保存为时间序列版本，再按来源窗口切片投影到自然分钟；投影不应反过来限制 AI 的窗口边界。

建议新增任务类型：

- `temporal_local_analysis`：下级 AI 局部窗口；
- `temporal_review`：上级 AI 多轮取证和窗口合并；
- `temporal_finalize`：停止、TTL 或用户请求触发的收尾检查。

任务仍使用现有队列租约、deadline、幂等键和版本竞争机制。工具调用不能绕过任务租约；租约失效后停止下一轮外部请求。

## 10. Provider 能力测试

现有能力测试需要从“能否看多张图片”扩展为“能否进行时间序列推理和受限工具调用”：

1. 有序图片与时间戳是否按顺序理解；
2. 相同活动跨多个时间点能否输出连续时间段；
3. 活动切换时能否保留边界不确定范围；
4. 证据不足时能否请求指定时间段的图片；
5. 工具返回后能否继续同一轮并最终结束；
6. 能否遵守 evidence ID、窗口范围和结构化 schema；
7. 工具调用过多、图片过期或响应截断时能否返回 partial；
8. 真实 Provider 的最大窗口、图片数、请求体和延迟是多少。

能力结果要按 Provider、模型、工具协议和结构化输出版本绑定。未通过多轮能力测试的模型只能运行单轮兼容模式，不能冒充支持上级 AI。

## 11. 失败、成本和安全

工具调用会增加请求数、Token、延迟和图片过期风险。每个 TemporalRun 应记录：工具轮数、现场图片数、参考图片数、请求字节数、输入／输出 Token、等待时间、未解决范围和最终状态。

超时或工具调用失败时：

- 保留已完成的下级结果和上级 partial 结果；
- 不把未查看范围标为 complete；
- 在 deadline 内可以从检查点继续；
- 超过 TTL 后标记证据过期，文字结果仍可读；
- 不把模型的工具参数直接转成文件路径或任意数据库查询。

模型看到的图片文字、参考描述和历史结果都是资料，不是工具指令。工具响应只返回白名单字段，避免提示注入导致越权读取。

## 12. 前端展示

前端继续使用分钟、事件和报告作为主要阅读入口，但应能表达：

- 该活动来自直接观察、AI 推断或两者混合；
- 上级 AI 是否仍在检查；
- 哪些时间范围 unresolved；
- 哪些结论来自工具取证；
- 原图过期后，文字时间线和推断依据仍然可读。

不显示未经校准的模型百分比置信度。可以显示确定性类别、边界范围、来源窗口和“需要复核”的状态。

## 13. 实施顺序与验收

### 阶段一：契约和 Provider 能力

- 定义时间窗口、时间段、工具调用和 partial 结果 schema；
- 保持现有分钟 API 兼容；
- 为 Provider 增加多轮工具能力测试；
- 用固定回放样例验证顺序、引用、截断和权限。

### 阶段二：单窗口下级 AI

- 移除提示词中的“每分钟独立返回”限制；
- 让一次请求输出跨分钟时间段；
- 后端只做证据、时序和版本校验；
- 以兼容投影生成现有分钟记录。

### 阶段三：上级 AI 多轮取证

- 实现三个受限工具；
- 实现 checkpoint、问题触发、常规滚动和收尾任务；
- 记录每一轮工具调用和费用；
- 对过期、租约失效和 partial 结果做恢复测试。

### 阶段四：长时间窗口

- 以 5 分钟窗口、30 秒重叠作为初始实验参数；
- 通过人工标注回放调整窗口、重叠和检查周期；
- 验证 10 分钟、20 分钟连续活动和多次活动切换；
- 验证真实断流不被 AI 跨越。

必须通过的核心回放场景：

- 连续写字、阅读、静坐等低运动活动；
- 中间遮挡、背影、过暗、镜头抖动和局部离开；
- 活动切换发生在窗口边界；
- 10～20 分钟连续活动；
- 多次切换和人物重新出现；
- 真实缺帧、断流、图片过期和工具调用中断。

验收指标不只看分类准确率，还要看：连续活动被错误切断率、活动被错误延长率、边界误差、工具主动取证命中率、未解决范围诚实率、证据引用合法率、TTL 内完成率和单位活动成本。

## 14. 当前状态声明

截至 2026-10-20：

- 现有单轮 Chat Completions、图片证据、结构化输出和分钟投影已经实现；
- 多轮消息、受限图片工具、上级 AI、TemporalWindow／TemporalRun 持久对象尚未实现；
- 现有 `sparse_analysis`、`dense_analysis` 和 `reconcile_minutes` 仍按旧契约运行；
- 本文中的 5 分钟窗口、30 秒重叠只是实验起点，不是已确认生产参数。
