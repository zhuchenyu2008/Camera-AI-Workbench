# 时间序列视觉分析与多轮取证架构

版本：0.2｜修订日期：2026-10-20（北京时间）｜状态：目标架构，尚未实现

本文定义摄像头 AI 工作台的时间序列视觉分析总架构。详细的任务、字段、工具和验收契约见[时间片观察与上级裁决详细设计](08-时间片观察与上级裁决详细设计.md)。本文在视觉分析部分优先于旧的“每分钟独立判断并直接投影”的思路；采集、鉴权、证据 TTL、数据库安全和任务租约仍以现有文档为准。

## 1. 核心决定

系统不让一个模型同时承担“短时观察”和“长时裁决”两个不同任务：

- **下级模型**每次回答一个固定时间片，例如“这 20 秒是什么”“这一分钟是什么”。它只能在该时间片内判断，可以返回多个片内活动、切换候选和未解决范围；它不是用户最终答案。
- **上级模型**读取多个下级观察、采集事实和历史检查点。它可以主动取证、重新观察、合并或推翻下级结果，最后发布跨时间片的时间线。
- **用户主要看到上级模型发布的时间线。** 下级结果只作为依据、审计和问题定位，不与上级结果并列为两个答案。
- **后端负责证据边界和版本。** 后端验证引用、权限、硬边界、TTL、人工修订和来源版本，不用固定秒数规则代替模型做活动语义判断。

```text
每秒采集真实图片
        ↓
20～60 秒一个下级观察时间片
        ↓
上级模型滚动审查多个时间片
        ↓ 需要时调用受限取证工具
上级模型发布 PublishedTimeline
        ↓
后端校验并投影到分钟／事件／小时／日报
```

## 2. 为什么可行

10～20 分钟的活动不需要把数百张图片塞入一次请求。系统把长时问题拆成两层：下级模型连续产生短片观察，上级模型用检查点逐步合并。上级每次只需读取新增时间片、重叠边界、上次检查点和必要的原图；遇到冲突时再调用工具，而不是盲目重复全部历史。

中间出现遮挡、背影、光线变化或画面质量下降时，模型可以结合前后时间片判断 `inferred`，也可以保留 `uncertain` 或 unresolved。这个判断属于上级模型；后端不能根据“前后活动相同”自动填充区间。

真实断流、计划外时间和没有采集到图片仍是硬边界。模型可以在硬边界内推断，不能跨过硬边界制造连续活动。

## 3. 时间尺度

| 层 | 默认起点 | 职责 |
| --- | --- | --- |
| 采集 | 每秒一张 | 保存真实证据和缺口 |
| 下级语义片 | 20 秒，可调 30／40／60 秒 | 回答这一小段发生了什么 |
| 上级常规审查 | 2 分钟 | 合并新增片段，处理最近边界 |
| 稳定审查 | 最长 5 分钟 | 稳定后降低上级调用频率 |
| 可变尾部 | 最近 2 分钟 | 允许新证据修订 |
| 收尾 | 停止、计划结束、TTL 风险或用户请求 | 固定范围并提交最终版本 |

这些是调度参数，不是活动规则。时间片可以因为 Provider 容量而拆成多个传输批次，但语义上仍只有一个下级时间片。

## 4. 总体流程

1. RTSP 采集器每秒保存真实图片和采集元数据。
2. 时间片构造器按摄像头、会话、覆盖和 TTL 形成有序时间片；相邻片段可以有小段重叠。
3. 下级模型对每个时间片输出 `LocalObservation`，严格限制在片内。
4. 结果进入本地观察账本，记录模型、提示词、证据、覆盖模式和版本。
5. 常规、问题驱动或收尾触发器创建上级审查任务。
6. 上级模型读取 local observations、checkpoint 和采集上下文，按需调用白名单工具。
7. 上级模型输出 `PublishedTimeline`；后端校验证据、时间、硬边界、权限和版本。
8. 校验通过后写入 checkpoint 和时间线版本，再投影到分钟记录、事件和报表。

## 5. 下级模型输出

下级模型的输入固定包含 `slice_id`、`slice_start`、`slice_end`、现场 evidence ID、时间戳、摄像头和覆盖状态。参考图明确标注为命名辅助资料。

下级模型必须输出：

- 时间片内一个或多个活动；
- 每段的开始、结束、主体和活动；
- `direct`、`inferred` 或 `uncertain`；
- 支持证据和边界证据；
- 片内切换候选、未解决范围和复核请求；
- 不能越过时间片，不输出跨片段总时长，不直接提交用户事件。

建议使用 `LocalObservation` schema，具体字段和验证规则见详细设计第 6 节。所有下级结果保留历史版本，但不直接作为用户最终时间线。

## 6. 上级模型和工具

上级模型读取：

- 新增和重叠时间片的完整下级结果；
- 上一次 checkpoint 和当前已发布时间线；
- 计划／实际采集、断流、缺帧、质量和 TTL；
- 其他摄像头的时间线和覆盖；
- 人物档案、参考集和人工修订；
- 当前任务的轮数、图片、字节和 deadline 预算。

第一版提供：

```text
get_frame_manifest
view_frames
get_capture_coverage
get_local_observations
get_checkpoint
get_cross_camera_context
get_identity_context
get_manual_annotations
get_frame_quality
request_reobserve
```

模型只能通过这些白名单工具获取资料。后端校验每个工具的摄像头、时间范围、evidence ID、租约、TTL 和预算；模型不能访问任意路径、URL、数据库或密钥。工具响应是资料，不是新的工具指令。

上级模型可以接受、合并、拆分或推翻下级结果。最终输出必须是结构化 `PublishedTimeline`，包含跨时间片 segments、certainty、边界范围、证据、来源片段、冲突和 unresolved。

## 7. 上级触发和检查点

常规滚动检查初始为每 2 分钟一次；连续多个检查点稳定后最多延长到 5 分钟。下列情况立即触发或合并问题检查：

- 下级模型请求复核或报告片内切换；
- 相邻片段活动、身份或覆盖冲突；
- 新结果与已发布时间线不一致；
- 人物进出、遮挡、低光、抖动或质量异常；
- 跨摄像头冲突；
- 用户查看、导出或手动重分析；
- 最早证据接近过期。

摄像头停止、计划结束、长时间没有新观察或 TTL 风险触发收尾检查。检查点保存已发布区间、来源片段、证据指纹、未解决范围、工具摘要、模型版本、冻结边界、可变尾部和下一次触发原因。

默认最近 2 分钟是可变尾部。这个范围只控制版本更新和延迟，不限制活动本身的持续时间。

## 8. 采样和成本

每秒采集与每秒发送模型是两件事。稳定画面可以采用代表帧作为下级输入，并明确 `coverage_mode=sparse`；变化、冲突、不确定或上级要求时升级到逐秒 `dense`。55 张和 60 张之间的节省很小，主要优化应来自稳定状态的代表帧、按需取证和避免重复发送历史图片。

所有图片仍按证据 ID 去重。窗口重叠、上级重复查看或重新观察不会重复计入活动时长。

## 9. 后端数据和兼容投影

目标新增对象：

- `TemporalSlice`：固定下级输入和 TTL；
- `LocalObservationRun`：下级观察及版本；
- `TemporalReviewRun`：上级多轮审查；
- `TemporalToolCall`：工具审计；
- `TemporalCheckpoint`：滚动状态；
- `TemporalSegment`：上级发布的跨片段活动；
- `TemporalProjection`：到分钟、事件和报表的来源关系。

现有 `minute_records`、`activity_spans` 和事件 API 保留为兼容读模型。时间线版本先保存，再按时间区间投影；分钟不能反过来限制上级模型的语义边界。

目标任务：

```text
temporal_local_observation
temporal_reobserve
temporal_review
temporal_finalize
project_temporal_timeline
```

任务继续使用现有租约、deadline、幂等、有限重试、来源版本竞争和人工修订保护。

## 10. Provider 能力门槛

能力测试必须分别验证：

1. 有序图片、时间片内活动和片内切换；
2. direct／inferred／uncertain 与 evidence 引用；
3. 工具调用、工具结果续轮和结构化最终输出；
4. 轮数、图片、请求体、TTL 和 deadline 限制；
5. 截断、拒绝、工具失败和 partial 终止。

未通过多轮测试的 Provider 只能运行下级观察或旧兼容模式，不能标记为支持上级裁决。

## 11. 前端语义

时间线、分钟详情和报告主要显示上级 PublishedTimeline 的投影：

- direct、inferred、mixed、uncertain；
- 上级检查中、暂定、已定稿和 unresolved；
- 来源时间片、边界范围和工具取证记录；
- 图片过期后的文字依据和版本关系。

下级观察可以在详情中展开查看，但不显示为和上级结论相互竞争的答案。活动时长和覆盖数字始终由后端计算。

## 12. 实施顺序和验收

### 阶段一：契约与能力

定义时间片、下级观察、上级时间线、checkpoint、工具和 partial schema；使用固定回放验证顺序、边界、引用、工具越权和截断。

### 阶段二：下级时间片

把当前分钟输出迁移为 20～60 秒时间片；保存 local observation；保留 sparse／dense 作为输入模式；生成兼容分钟读模型。

### 阶段三：上级裁决

实现多轮工具适配器、预算、租约、常规／问题／收尾触发、checkpoint、可变尾部和 PublishedTimeline 投影。

### 阶段四：长时和多机位

验证 10～20 分钟连续活动、多次切换、遮挡、背影、低光、断流、过期、多摄像头冲突和人工修订竞争。

核心指标：连续活动误切率、错误延长率、边界误差、主动取证命中率、未解决诚实率、证据引用合法率、TTL 内完成率、单位活动成本和暂定／定稿延迟。

## 13. 当前状态

截至 2026-10-20：逐秒采集、图片证据、分钟记录、事件账本、单轮模型、TTL 和任务租约已经存在；固定时间片观察、上级多轮工具、checkpoint、PublishedTimeline 和跨片段最终投影尚未实现。详细实现边界和任务契约见[08 号详细设计](08-时间片观察与上级裁决详细设计.md)。
