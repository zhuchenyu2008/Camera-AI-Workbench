# 摄像头 AI 总结工作台 — 产品需求文档（PRD）

- **版本**：1.0
- **状态**：需求基线，可进入技术方案与实现拆分
- **产品形态**：单用户、自托管 Web 工作台
- **部署环境**：Linux 服务器 + Docker Compose
- **默认时区**：Asia/Shanghai；所有内部时间统一存 UTC，界面按用户时区显示
- **核心输入**：一个或多个 RTSP 摄像头
- **AI 接口**：通用 OpenAI-compatible Chat Completions 协议

---

## 1. 产品概述

产品从一个或多个 RTSP 摄像头按每秒一帧采集并在本地短期保存图像。轻量本地检测负责筛除高度重复画面、发现画面变化并选取证据帧；云端 AI 按三层流程生成分钟观察、活动时间轴及小时/日总结。用户可追溯 AI 判断所依据的照片、观察记录与推断区间，并可修正活动名称和时间。

**目标体验**：用户打开工作台后，能看到实时采集/分析状态；随后能在时间轴上读到“09:00–09:20 写作业、09:20–09:30 玩手机、09:30–09:31 写作业、09:31–09:41 玩手机、09:41–09:48 整理桌面”这类按活动切分的记录。中间若有短时遮挡，系统可在证据支持时推断连续活动，同时明确标出这是推断而非直接观察。

### 1.1 产品原则

1. **每秒采集，按需分析**：采集与上传/调用 AI 是不同动作。每秒帧先落本地；重复帧优先去重或降采样。
2. **分层各司其职**：第一层记录局部观察；第二层负责跨分钟归纳、活动分段及有边界的连续性推断；第三层负责统计和总结。
3. **时间轴以第二层为准**：第一层只作为临时状态和证据；第二层结果是主时间轴；第三层不得改写第二层事实记录。
4. **证据与不确定性可见**：区分直接观察、推断、未知和处理中，不允许把推断伪装成直接观察。
5. **本地优先、云端可替换**：图像先存于自托管服务；AI 经统一 OpenAI-compatible 网关调用，可配置多个端点和模型。
6. **资源可控**：本地默认只做缩放、差异/重复检测、抽帧、存储和任务调度，不要求 GPU，不运行本地视觉大模型、OCR 或人脸身份识别。

## 2. 目标、非目标与成功指标

### 2.1 产品目标

- 支持多路 RTSP 流持续采集，默认每路每秒生成一张本地快照。
- 在普通稳定场景下减少送给 AI 的图片数量；发现变化后调取前后缓存并临时升为高精度分析。
- 第一层按分钟记录观察；第二层默认每 5 分钟形成一个分析批次，但必须在批次内部输出任意数量的活动段，而不是整段只给一个标签。
- 第二层可以结合前后锚点补全有限的遮挡/缺失区间，并保留推断标记与置信度。
- 第三层生成小时总结和日报，汇总活动类型、时长、切换和未知区间。
- 提供匿名人物聚类/人物档案，不识别或区分“本人”和“其他人”，不自动赋予真实姓名。
- 允许逐层配置不同 OpenAI-compatible 服务地址、密钥和模型，并可查看每次 AI 使用量。
- 让用户自行设置普通帧、事件帧、时间轴与总结的保留期。

### 2.2 首版非目标

- 多租户、公开注册、团队协作、权限角色体系。
- 摄像头云端管理、云存储托管服务、移动端原生应用。
- OCR、屏幕文字识别、文档内容理解。
- 人脸身份识别、真人姓名推断、本人/他人区分。
- 首版强制隐私遮罩 UI（数据结构可预留扩展）。
- 每日/月度费用硬上限或达到上限后自动停机。
- 本地部署视觉大模型。
- 保证对摄像头不可见的活动作出确定性判断。

### 2.3 发布验收指标（在指定测试环境与测试集测量）

- 稳定网络下，每路摄像头的计划采集点、成功帧、断流和补采失败均可统计；连续 24 小时采集成功率目标不低于 99%，断流期间必须明确记录缺口，不能伪造照片。
- 第一层及第二层每个任务均可追踪状态、输入帧数、输出、耗时、模型和错误；服务恢复后待处理任务可继续执行。
- 人工标注测试片段中，时间轴能分开至少两个活动段；活动边界误差目标中位数不超过 30 秒。遮挡推断单独计算，不混入直接观察准确率。
- 遮挡测试中，系统能在“遮挡前后同一活动、无反证、缺口未超过配置上限”时给出带推断标记的连续活动；存在冲突证据时必须输出拆分或未知，而非强行合并。
- 每条最终活动可回溯至相关分钟观察、证据照片/照片缺口、模型调用及用户修改记录。

## 3. 用户、部署及默认配置

### 3.1 用户模型

- 单用户、单个自托管实例。
- 可配置多个摄像头、AI 服务端点和模型。
- Web UI 默认只在用户自己的网络/认证边界内访问；首版不提供公共 SaaS 账号体系。

### 3.2 默认产品参数

| 配置 | 默认值 | 可配置范围/说明 |
|---|---|---|
| 摄像头来源 | RTSP | 多路；每路独立启停和健康状态 |
| 采集频率 | 每秒 1 帧 | 首版默认值；允许按摄像头设置 |
| 第一层窗口 | 60 秒 | 分钟级观察；窗口边界按整分钟对齐 |
| 第二层批次 | 5 分钟 | 可选 5/10 分钟；窗口内必须返回多个活动段 |
| 高精度前置缓存 | 30 秒 | 用户可配置 |
| 高精度后置观察 | 60 秒 | 用户可配置；活动仍持续时可延长 |
| 单次高精度最长时长 | 5 分钟 | 防止触发条件异常导致无限高频上传；可配置 |
| 稳定场景 AI 取样 | 最多 6 张/分钟 | 默认从 10 秒间隔候选帧中去重；只作为初始参数，按模型和实测调整 |
| 事件/变化帧 | 额外加入关键帧 | 去重后最多 12 张/分钟；高精度模式可按 1 fps 提交完整事件区间 |
| 普通原始帧保留 | 1 小时 | 用户可选择保留时长或关闭自动删除 |
| 事件帧保留 | 6 小时 | 用户可选择保留时长或收藏为长期保留 |
| 时间轴/总结保留 | 由用户选择 | 提供保留时长、永久保留和清理选项 |
| 连续性推断最大缺口 | 5 分钟 | 用户可调；超过上限默认未知，除非第二层有额外充分证据 |
| AI 费用限制 | 无硬性上限 | 展示调用量和费用估算，不因费用自动停用 |
| OCR / 人脸识别 | 关闭/不支持 | 首版范围外 |

上述抽帧数量是产品初始策略，不是对不同模型的最佳值承诺。必须在实际摄像头、图片尺寸与模型上验证后允许调整。

### 3.3 资源基线

首版以无 GPU 的 Linux Docker 主机运行。建议开发/验收基线从 4 vCPU、8 GB RAM 开始，覆盖 1–4 路常见 1080p H.264 RTSP 流的采集、抽帧、任务队列和 Web 服务；实际支持路数必须通过目标硬件、编码格式及 AI 延迟压测确定。不要将建议基线宣传为所有摄像头组合下的性能保证。

## 4. 术语与数据可信等级

- **帧（Frame）**：摄像头在某一采集时间点产生的图片及其元数据。
- **分钟观察（Minute Observation）**：第一层对一分钟内输入帧、变化点和可见情况的结构化记录。
- **活动段（Activity Segment）**：第二层给出的时间区间、标准活动、描述、证据和可信等级。
- **直接观察**：时间区间有可见图片证据支撑。
- **推断补全**：区间本身被遮挡/缺帧，第二层依据前后锚点及无反证推断连续性。
- **未知**：证据不足或互相冲突，系统不作活动判断。
- **临时结果**：第一层结果或第二层尚在处理的结果，可被后续任务修订。
- **最终结果**：第二层已完成该窗口及必要相邻窗口校正的活动记录；仍可由用户修正。
- **匿名人物簇**：用于统计重复出现的视觉人物，不对应真实身份。

## 5. 系统流程与分层职责

```text
RTSP 摄像头（多路）
  → 采集服务：每秒取帧、本地落盘、断流检测、前置环形缓存
  → 轻量本地检测：小图灰度/帧差/重复帧/稳定性信号
  → 智能取样：稳定帧 + 变化关键帧；事件触发时纳入前后缓存
  → 第一层 AI：每分钟观察/候选活动/变化和遮挡记录
  → 第二层 AI：每 5 分钟批次整合、活动切段、跨窗口连续性判断和有限补证
  → 第三层 AI：每小时总结、日报和活动统计
  → 工作台：实时状态、可追溯时间轴、证据、用量及设置
```

### 5.1 第一层：一分钟视觉观察 AI

**职责**：描述本分钟内“看见什么”，识别候选活动、时间变化、人物/物体的可见状态、遮挡与证据缺口。允许给出不确定或未知，不负责对长时间缺口作最终连续性判断。

**输入**：时间范围、所选照片、相邻分钟摘要（如有）、本地差异信号、摄像头标识、当前采集/分析模式。

**输出**：结构化观察、候选活动（可多项及子区间）、开始/结束估计、置信度、证据帧 ID、可见/遮挡/断流区间、是否需补图、标准活动候选。

**执行策略**：

1. 初始配置下，每分钟最多提交 6 张去重的代表帧；有变化时追加关键帧，普通模式每分钟总量上限 12 张。
2. 稳定场景可以复用上一分钟状态并只提交稀疏心跳帧；实现允许跳过重复模型调用，但必须产生分钟记录，注明其来源是“本地稳定延续”而非 AI 直接观察。
3. 高精度事件将环形缓存中的前置帧、触发帧及后置帧组成一个或多个分钟任务；配置允许按 1 fps 将事件区间完整送入 AI。
4. 纯本地稳定延续不得被标成“第一层 AI 已确认”。UI 必须区分“AI 观察”和“本地稳定延续”。

### 5.2 第二层：5 分钟活动推理与时间轴 AI

**职责**：面向用户产出最终活动时间轴。不是对 5 分钟做单句总结，也不是把五条分钟记录机械拼接；需要识别窗口内多个活动段，判断切换点，跨分钟合并相同活动，必要时请求局部证据，并对有限缺口作有边界的推断。

**输入**：当前批次的分钟观察、前后相邻批次活动摘要、直接观察帧 ID、变化/稳定信号、遮挡/断流标记、用户纠正、活动目录。

**处理规则**：

1. 先读取结构化分钟观察，不默认重新看完整 300 张原图。
2. 检查活动候选冲突、活动切换、低置信区间、长遮挡和相邻窗口边界；仅对需要复核的时间段调用取图工具。
3. 窗口内部允许输出多个活动段，活动段可短至约 1 分钟；不可为了对齐 5 分钟批次而合并不同活动。
4. 遮挡前后锚点活动相同、场景/人物状态相容、无相反证据、缺口未超过配置上限时，可合并为连续段；被遮挡子区间必须标为推断，并降低/单独报告置信度。
5. 遮挡前后活动不同或证据冲突时，优先给出切换区间或未知区间，不可依据“常理”擅自填充。
6. 对窗口边界保留可修订能力：后续窗口的新证据可以提出相邻活动合并/拆分；每次自动修订需记录版本、原因和涉及证据。不得无痕改写已展示结果。
7. 缺少足够证据时输出 `unknown`，而非强行从活动目录中选一个活动。

**第二层工具**（由服务端执行并完整审计）：

- `get_frames(camera_id, start, end, limit)`：按时间范围取帧，限制最大帧数。
- `get_keyframes(camera_id, start, end, limit)`：获取变化点、窗口边界及代表帧。
- `compare_frames(frame_a, frame_b)`：返回轻量差异摘要及引用帧。
- `crop_frame(frame_id, normalized_region)`：裁剪指定区域；无 OCR。
- `get_local_signals(camera_id, start, end)`：读取帧差、重复帧、断流和遮挡元数据。
- `get_adjacent_activity(camera_id, start, end)`：读取相邻第二层活动摘要。
- `request_high_precision(camera_id, start, end)`：对仍可用缓存/原始帧触发补充分析。

所有工具参数都须做时间范围、帧数、摄像头 ID、文件访问权限和调用次数校验；AI 不可传入任意文件路径。每个任务设最大工具轮数和最大帧数，达到上限后输出不确定/待复核状态。

### 5.3 第三层：小时总结与日报 AI

**职责**：对第二层活动段做小时总结、日报和分类统计；可指出数据缺口、推断比例和异常，但不改写源活动段。

**输入**：已完成的第二层活动段、用户修正、活动分类和人物匿名档案；必要时只引用证据索引，不默认重新读取原图。

**输出**：自然语言总结、活动时长/次数、连续活动区间、切换次数、未知时长、推断时长、摘要来源的活动段 ID、生成模型/时间。

**重生成**：用户修正活动后，系统将相关小时总结和日报标记为“待更新”；重新生成后保存新版本，保留旧版本审计记录。

## 6. 本地变化检测与高精度状态机

### 6.1 本地检测边界

检测在低分辨率缩略帧上运行，默认不调用视觉大模型。首版可组合：

- 小尺寸灰度帧差或感知哈希；
- 重复帧/冻结画面检测；
- 摄像头连接、解码和时间戳健康状态；
- 多帧平滑阈值，抑制闪烁、噪点和自动曝光导致的单帧误报。

首版不承诺本地识别“正在写作业/玩手机”等语义活动。语义由云端 AI 完成。可根据单机实测调整缩放尺寸、检测间隔和阈值，以控制 CPU 使用。

### 6.2 状态流

```text
STARTING → CAPTURING → LOCAL_SCREENING → L1_PENDING → L1_PROCESSING
→ L1_READY → L2_PENDING → L2_PROCESSING → TIMELINE_READY
→ L3_PENDING → SUMMARY_READY
```

附加状态：`CAMERA_OFFLINE`、`CAPTURE_GAP`、`LOCAL_STABLE_CONTINUATION`、`NEEDS_MORE_EVIDENCE`、`AI_RETRY_WAIT`、`AI_FAILED`、`RETENTION_CLEANUP`。

### 6.3 触发策略

- 画面差异达到配置阈值并持续达到确认帧数时，创建事件，不因单帧闪变直接触发。
- 事件触发时冻结前置环形缓存，继续收集后置帧；事件边界、升级与降级时间写入数据库。
- 事件持续时可以延长高精度模式；达到最长时长后必须降级或重新判断，避免无限高频提交。
- 高精度结束条件默认是后置观察结束且连续一段配置时间稳定；UI 可查看升级原因和降级原因。
- 同一摄像头重叠事件合并为一个事件任务，避免重复上传。

## 7. 功能需求

优先级：**P0** 为首版必须；**P1** 为首版可在主链路后完成；**P2** 为预留/后续。

### 7.1 摄像头管理

**CAM-01（P0）添加/编辑/删除 RTSP 配置**

- 用户可配置名称、RTSP URL、启用状态、采集频率、帧尺寸/质量、采集时区继承策略。
- URL 凭据不得明文出现在日志、前端错误详情或 AI 请求提示词中。
- 增加连接测试，展示成功/失败、可读流信息和错误原因（脱敏）。
- 删除摄像头只停止后续采集；是否删除历史数据须由用户单独确认，不能隐式清除。

**CAM-02（P0）多路独立运行**

- 任一路断流不阻塞其他摄像头。
- 每路显示在线、离线、重连中、最近成功帧、连续失败次数和采集缺口。
- 采用可配置退避重连；恢复后生成断流区间，不对缺失帧进行合成。

### 7.2 采集、存储、留存

**CAP-01（P0）每秒快照**

- 以采集端时间戳记录预期采集点、实际采集时间、帧序号和摄像头 ID。
- RTSP 无可用帧时记录缺失状态；不得重复旧帧冒充新帧。
- 写盘采用临时文件 + 原子完成标记；不完整文件不进入 AI 队列。

**CAP-02（P0）环形缓存与智能抽帧**

- 保留足够的本地前置缓存供变化触发使用。
- 支持按相似度去重、稳定抽样、变化关键帧及高精度事件帧集合。
- 记录每张帧是否送入模型、送入哪一任务、是否因过去保留期而无法取回。

**CAP-03（P0）可配置留存**

- 普通帧默认 1 小时，事件帧默认 6 小时；用户可修改时长、关闭自动清理或收藏数据。
- 提供磁盘占用、每路数据量、即将清理量和最近清理结果。
- 清理任务只删除已过期且未收藏/未被有效任务引用的数据；数据库引用与文件清理保持一致，失败可重试。
- 清理不得影响已生成的活动文本与摘要，除非用户另行选择删除。

### 7.3 AI 服务配置与使用量

**AI-01（P0）通用 OpenAI-compatible 接入**

- 统一使用可配置 `base_url`、API Key、模型名、超时、最大重试、并发数的服务端适配层。
- 首版兼容目标为 OpenAI-compatible Chat Completions 请求格式；多模态层要求支持图像输入；第二层优先要求兼容工具调用。可选 `response_format` 等增强能力须通过连接测试探测，不作为所有服务必备条件。
- 用户可为 L1/L2/L3 分别选择端点和模型，并可配置备用端点。
- 连接测试包含文本、图像（对视觉层）和结构化输出/工具调用能力检查；结果标明实际探测到的能力。
- 服务商不兼容时给出明确错误，不得静默将图片丢弃或伪装成成功。

**AI-02（P0）凭据与网络安全**

- API Key 只由后端保存并加密/受系统密钥保护；前端仅显示脱敏结果。
- 请求体和应用日志不得记录明文密钥、完整签名图片 URL 或不必要图像内容。
- 默认只允许用户配置的服务地址；对 URL 做协议、DNS/IP 和重定向校验，明确处理私网/本地端点允许策略，降低 SSRF 风险。自托管本地模型端点需作为显式配置选项允许。
- 出站 TLS 校验默认开启；不得因兼容性静默关闭证书验证。

**AI-03（P0）任务队列、重试和版本**

- AI 调用进入持久化队列，支持重启恢复、指数退避、最大重试和人工重试。
- 相同摄像头、时间窗口、输入版本和提示词版本采用幂等任务键，避免重复扣费。
- 每次请求记录：层级、提供方标签、模型、时间范围、输入帧数/字节、输入输出 Token（服务返回时）、耗时、工具调用数、重试数、状态和费用（可计算时）。
- 不需要费用预算硬停止；用量页展示按日、摄像头、层级和模型过滤的统计。未知费用显示“未返回/无法估算”，不能写 0 冒充免费。

### 7.4 第一层分钟观察

**L1-01（P0）分钟任务**

- 每分钟产生分钟记录；如跳过模型调用，记录跳过原因及本地稳定延续来源。
- 任务结果包含观察事实、候选活动（可多段）、时间估计、置信度、证据帧、遮挡/断流和不确定说明。
- 无法判断时必须允许 `unknown`；结构化输出失败最多执行配置的修复重试，仍失败进入 `AI_FAILED` 并保留原始响应的脱敏诊断摘要。

**L1-02（P0）实时状态展示**

- 最新分钟未出结果时显示“第一层 AI 识别中”；如本地跳过则显示“画面稳定，沿用上一状态（本地判断）”。
- 显示最近完成时间、帧数、任务耗时、失败/重试状态。

### 7.5 第二层活动时间轴

**L2-01（P0）5 分钟分析窗口及多段输出**

- 默认每 5 分钟执行一个批次；批次中可输出零个或多个活动段。
- 每个活动段含开始/结束、标准名称、AI 自由描述、分类、置信度、证据覆盖率、直接观察/推断子区间、来源分钟记录及版本。
- 可识别短时活动并划分窗口内部起止，不得将整个 5 分钟强制映射到单一活动。

**L2-02（P0）跨分钟/遮挡连续性推断**

- 输入上下文覆盖相邻时间；遮挡前后相同活动可以跨缺口合并，但必须符合第 5.2 节规则。
- 输出同时表达活动段总区间和子区间证据等级。
- 对连续性推断给出推断依据、缺口时长、前后锚点和置信度。
- 超出最大缺口、前后锚点不一致或存在反证时，输出未知/切换/待补证，而不是自动补全。

**L2-03（P0）时间轴与修订**

- 最终用户呈现以第二层结果为准；第一层仅在第二层未完成时作为临时层。
- 视觉区分直接观察、推断补全、未知/证据不足、处理中和失败。
- 用户可修改活动名称/分类和起止时间，可拆分、合并、标未知、锁定、重新分析。
- 每次修改保留修改前后值、时间、来源（用户/自动）、原因和操作者（本产品单用户）。
- 已锁定段不被自动任务覆盖；重新分析须明确告知将对未锁定数据产生的变更。

### 7.6 活动目录与归一化

**ACT-01（P0）标准活动目录**

- 首装提供基础活动名称和大类，如学习、工作、娱乐、生活、休息、未知；默认名称包括写作业、玩手机、整理桌面、看书、使用电脑、吃饭、睡觉等。
- AI 可以提供自然语言描述，但须优先映射到现有标准活动 ID。
- 记录 `canonical_activity`、`display_description`、`category`、`aliases`，避免近义词造成统计碎片。
- 无合适条目时输出“新活动候选”，默认不直接批量污染目录；用户可新增、合并别名或映射到已有活动。
- 允许用户维护目录和同义词；用户修改的映射优先于模型建议。

### 7.7 第三层总结

**L3-01（P0）小时总结和日报**

- 按本地时区小时边界及自然日生成；跨时区/夏令时的内部存储仍用 UTC 并按配置日历计算。
- 汇总第二层活动段时长、次数、主要活动、切换、未知/推断比例。
- 每条总结保留来源活动段 ID；活动段修改后标记摘要待重算。
- 若数据不完整，需明确写出采集/分析缺口；不得把未分析时段称为“没有活动”。

### 7.8 匿名人物档案

**PER-01（P1，主链路后完成）匿名人物聚类**

- 仅建立匿名 `person_cluster_id`，用于重复出现聚类和活动证据；不输出真实姓名，不区分本人/他人，不做人脸身份识别。
- 每个档案存首次/最近出现、出现事件、代表帧引用、聚类置信度和人工合并/拆分历史。
- 用户可关闭人物聚类，或删除某档案及其关联特征；删除后关联活动文本仍可保留但人物链接清空。
- 聚类不确定时使用 unknown，不强行归并。

### 7.9 首页与分析记录

**UI-01（P0）工作台首页**

- 摄像头卡片显示连接状态、最近帧、当前分析阶段、临时活动/最终活动、当前普通/高精度模式及存储量。
- 总览显示当前小时状态、队列待处理数、AI 今日调用量/图片数/Token/费用估算（可得时）。
- 允许按摄像头与时间打开历史时间轴。

**UI-02（P0）活动详情与证据**

- 点击活动段可查看开始/结束、标准名称/自由描述、直接观察与推断区间、置信度、相关证据帧、第一层分钟记录、第二层判断摘要、AI 工具调用概要及修改历史。
- 若原始照片已按保留策略清理，详情仍显示“证据照片已过期”，不隐藏缺失事实。

**UI-03（P0）设置和用量**

- 摄像头、AI 端点/模型、采样模式、窗口、留存、活动目录、人物聚类、时间区间均可配置。
- 用量报表按天/层级/摄像头/模型查询和导出 CSV；无可用费用数据时仅展示 Token/图片/调用数。

## 8. OpenAI-compatible API 接入要求

### 8.1 产品定义的兼容子集

“通用 OpenAI 协议”在本 PRD 中指通过可配置 `base_url` 调用 OpenAI-compatible Chat Completions 风格接口，而不是绑定某个 SDK 或供应商品牌。首版由统一后端网关构造 `messages`、多模态图片内容及必要的工具定义；不兼容供应商的专有功能不纳入核心业务逻辑。

- L1/L2 需要图像输入能力。
- L2 需要调用证据查询工具；优先使用兼容的 function/tool calling。若某端点不支持原生工具调用，适配层可使用受限 JSON action 循环，但必须通过连接测试并遵循相同工具权限、轮次和帧数上限。
- L3 只需文本和稳定 JSON 输出。
- API 路径拼接规则须可配置且避免重复 `/v1`；连接测试报告最终请求目标（隐藏凭据）。
- 图片传输可采用 API 兼容的 image URL 或 base64 data URL；默认使用仅在服务端可取、短时有效或直接编码的方式，不向模型暴露宿主任意路径。
- 请求超时、图片尺寸、并发、速率限制、重试策略按模型端点配置。
- 模型不返回 Token 用量或费用时，UI 标为未提供；可保留本地图片数和请求数。

### 8.2 提示词及结构化结果治理

- L1/L2/L3 提示词分别版本化；每个 AIJob 保存 prompt version 和输出 schema version。
- 模型输出先做 JSON Schema 校验、时间范围校验、枚举校验、证据帧归属校验和重叠/空区间校验，再写入正式记录。
- 模型不得生成其输入中不存在的 `frame_id`；证据必须引用任务可访问的帧。
- 不可信图片内容作为观察对象，不作为系统指令；忽略画面中可能出现的提示注入文本（本产品不做 OCR，但图像模型仍需此约束）。
- 校验失败可做一次结构修复请求；仍失败时保留失败状态，不静默丢弃或写入伪结构。

## 10. 页面与关键交互

### 10.1 实时工作台

- 顶部：当前本地时间、实例运行状态、待处理任务数、AI 使用量入口。
- 摄像头列表/卡片：在线状态、最近一帧缩略图、采集缺口、当前模式、正在处理的层级。
- 实时状态文本示例：
  - “采集中 · 等待本分钟观察”
  - “第一层 AI 识别中 · 已提交 8 张图”
  - “画面稳定 · 沿用上一状态（本地判断）”
  - “第二层 AI 正在整理最近 5 分钟”
  - “写作业 · 第二层已整理”
  - “摄像头离线 · 09:41:12 起无新画面”

### 10.2 时间轴

- 默认按摄像头和日期查看，支持缩放到小时、5 分钟和活动段。
- 一条活动段可含直接观察和推断子区间；不能用单一颜色掩盖内部证据等级。
- 图例：实色=直接观察；斜纹=推断；灰色=未知/证据不足；虚线/动画=处理中；错误标记=分析失败。
- 处理未完成时先显示第一层临时观察或“正在处理”；第二层完成后替换为第二层活动段并保留来源。
- 相邻窗口稍后修订时显示“已更新”提示，可查看变更前后内容。

### 10.3 活动修订

用户编辑活动段时，可选择是否同步更新标准目录映射；活动段锁定后自动分析不能覆盖。修改后触发相关小时/日报失效标记。删除证据照片和删除活动记录是不同操作，并分别确认。

## 11. 运行、队列与故障处理

### 11.1 任务优先级

1. 摄像头采集与帧落盘；
2. 已触发事件的第一层高精度观察；
3. 普通第一层分钟观察；
4. 第二层活动整理；
5. 第三层总结；
6. 非必要历史重算。

AI 故障不得阻塞采集；队列应对每路摄像头实施并发限制，避免单个模型慢请求拖垮实例。

### 11.2 重试与补算

- 网络/限流/临时服务错误可退避重试；认证失败、模型不支持图像、结构持续无效等错误需停止自动快速重试并显示配置问题。
- 服务不可用时继续本地采集，任务状态为待重试；超过帧保留时间后如输入已清理，状态改为“证据已过期，无法补算”，不能自动用新帧替代。
- 用户可针对时间段手动补算；页面展示重算范围、预计图片数和可能覆盖的未锁定结果。
- 应用升级或容器重启后，已完成任务不得重复产生新活动段；运行中的任务可安全恢复或标记需重试。

### 11.3 运行监控

至少提供：RTSP 连通性、采集帧率、解码错误、磁盘可用空间、队列深度、AI 请求成功率/耗时、重试数、容器健康状态及最后成功分析时间。单用户首版无需复杂外部监控平台，但日志须可由 `docker compose logs` 查看。

## 12. 部署与安全要求

### 12.1 Docker Compose

- 提供 Linux `docker compose up -d` 部署路径、健康检查、持久化数据卷、环境变量模板和升级说明。
- 服务逻辑可按采集、Web/API、后台 AI Worker 分容器，但首版避免不必要的微服务拆分；单机 Compose 可运行全部核心组件。
- RTSP 凭据、AI Key、SQLite/数据库和帧存储不得放入镜像层。
- 容器重建后数据库、图片与配置按卷持久化；初始化和升级脚本需幂等。
- 支持备份数据库和用户配置；图片备份是否开启由用户选择。

### 12.2 访问和凭据

- 单用户不等于无安全措施。提供至少一种本地登录/访问令牌配置方式，并说明反向代理 TLS 部署。
- 默认不把 API Key 发给浏览器。
- 管理 API、图片访问、任务重试、配置修改和删除操作均需认证。
- 摄像头画面可能涉及敏感个人信息：设置页明确说明哪些帧会发到选定 AI 端点，并显示当前端点和留存时间。
- 删除 AI Provider 后，按配置处理其密钥；日志不保留密钥。

## 13. 验收场景

### AT-01 常规采集

输入：一路稳定 RTSP 摄像头，运行 30 分钟。

预期：每秒计划点有采集结果或明确缺口记录；每个分钟有第一层 AI 观察或本地稳定延续记录；没有重复帧被伪装成新帧；首页能显示运行状态。

### AT-02 低变化画面与资源控制

输入：摄像头连续拍摄基本静止桌面。

预期：本地缩略图差异被平滑；近重复帧不全部提交云端；AI 使用量能反映实际发送帧数；本地不启动 OCR/人脸/视觉大模型。

### AT-03 变化触发高精度

输入：用户从写作业切换为拿起手机。

预期：本地变化检测触发事件；收集配置的前置缓存、触发点和后置帧；L1 返回候选活动切换及证据；L2 在 5 分钟结果中输出两个独立活动段及可追溯边界。

### AT-04 单个 5 分钟批次含多个活动

输入：前 2 分钟写作业，后 3 分钟玩手机。

预期：L2 输出“写作业”和“玩手机”两个活动段及切换时间，不得只给“写作业/玩手机”一个混合段。

### AT-05 两分钟遮挡、前后活动相同

输入：遮挡前 10 秒和遮挡后 10 秒都支持写作业；中间 2 分钟遮挡；无反证。

预期：L1 如实标遮挡；L2 可输出覆盖完整时间的“写作业”，同时把 2 分钟子区间标记为推断，列出前后锚点和置信度。

### AT-06 遮挡前后活动冲突

输入：遮挡前写作业、遮挡后玩手机。

预期：L2 不把整个缺口强行判作任一活动；输出边界不确定/未知子区间或请求补证。

### AT-07 RTSP 断开

输入：采集期间网络中断 3 分钟。

预期：采集服务自动重连；生成准确缺口；其他摄像头继续工作；AI 与总结不把缺失时段描述为静止/无活动。

### AT-08 AI 服务不可用

输入：OpenAI-compatible 端点返回超时或 429。

预期：采集继续；任务排队并按策略重试；UI 状态准确；恢复后可完成任务且不生成重复活动段。

### AT-09 模型输出非法结构

输入：模型返回无效 JSON、错时间、无效帧 ID 或重叠区间。

预期：校验拒绝该结果，进行有限修复或进入失败/待人工重试；不写入无效正式时间轴。

### AT-10 留存与收藏

输入：普通帧超过 1 小时、事件帧超过 6 小时，另有收藏帧。

预期：普通/事件帧按用户策略清理；收藏内容按策略保留；时间轴仍显示证据过期提示；清理失败可见且可重试。

### AT-11 活动同义词

输入：模型输出“做数学题”“写数学作业”，目录有“写作业”。

预期：记录统一标准活动 ID，保留各自具体描述；统计不会产生两个重复活动；用户可纠正目录映射。

### AT-12 小时总结和日报

输入：一小时内含多种活动、未知段和推断段。

预期：L3 汇总时长与次数，明确区分推断/未知；源活动段可点击追溯；修改活动后摘要标为待更新并生成新版本。

### AT-13 多 AI 端点配置

输入：L1/L2/L3 配置不同 OpenAI-compatible base URL 和模型。

预期：各层按映射调用；视觉能力不足、认证失败、工具调用不兼容均在连接测试中明确显示；密钥不暴露给前端或日志。

### AT-14 匿名人物档案

输入：同一人物在不同时间重复出现。

预期：系统可生成匿名 cluster；不推断真实姓名，也不标注本人/他人；用户可关闭、合并或删除聚类。

## 14. 首版交付切分

尽管首版目标覆盖完整主链路，仍建议按可验收增量实现，不缩减最终范围：

1. **基础运行层**：Docker Compose、单用户认证、RTSP 多路采集、帧存储、留存设置、健康状态。
2. **分析底座**：本地差异/去重、事件缓冲、持久化任务队列、OpenAI-compatible AI Gateway、使用量日志。
3. **L1/L2 主链路**：分钟观察、五分钟多段活动整理、工具补证、遮挡推断、证据和可修订时间轴。
4. **总结与工作台**：小时总结、日报、活动目录、活动编辑、用量页。
5. **匿名人物档案**：仅在主时间轴稳定后并入首版完整验收；不得阻塞采集和时间轴基础能力。
6. **稳定性验收**：24 小时运行、断流/重启/AI 限流/磁盘清理/多摄像头压力测试。

每个增量都必须可独立启动、迁移和回滚；数据库结构采用版本化迁移。

## 15. 首版决策汇总

- 单用户、自托管，Linux + Docker Compose。
- 支持多个 RTSP 摄像头；每路默认每秒本地采集一张。
- 本地仅做低资源画面变化、相似帧筛选、缓存、存储和队列，不运行 OCR、视觉大模型或人脸身份识别。
- 智能抽帧为默认：稳定状态少量取样，变化后使用缓存并进入高精度模式。采集频率为每秒一帧（1 fps）；严格模式指每分钟提交该分钟采集的 60 张帧。
- 第一层按分钟记录可见事实和候选活动；必要时可通过严格模式提交一分钟 60 张图。
- 第二层默认每 5 分钟执行，但必须输出窗口内部多个活动段，并依据前后证据作有限、显式标注的遮挡连续性推断。
- 第三层生成小时总结和日报，不覆盖第二层活动记录。
- AI 使用 OpenAI-compatible Chat Completions 风格接口；不同层可绑定不同服务地址/模型，支持能力探测与备用端点。
- 普通帧默认保留 1 小时、事件帧默认 6 小时；用户可修改留存、收藏和长期保留策略。
- AI 用量可查询，无费用硬上限。
- 活动名称采用“标准目录 + AI 自由描述 + 用户确认新增/归并”。
- 人物只做匿名聚类，不识别真实身份，不区分本人/其他人。
- 首版不做 OCR，不强制隐私遮罩。

## 16. 实施前必须做的技术验证

以下属于实现前的 spike，不改变本 PRD 的产品要求：

1. 选定 2–3 种实际 RTSP 摄像头，测量 1 fps 快照的时间准确度、断流恢复、解码 CPU 和图片大小。
2. 对目标 OpenAI-compatible 端点逐个验证多图输入、图片尺寸/编码、工具调用或 JSON action、Token usage 返回和限流行为；兼容性按端点/模型分别记录，不能仅按供应商品牌推定。
3. 测量 6 张稳定抽样与高精度 60 张/分钟在活动切换和遮挡场景下的准确率、延迟和用量，再校准默认阈值。
4. 测量用户设定留存期下的磁盘增长、清理并发与数据库一致性。
5. 用人工标注样本评估直接观察与遮挡推断两类质量，分别呈现指标，避免以总体准确率掩盖推断错误。

> 本文是产品需求基线；具体阈值、模型选型、存储引擎和部署拓扑可在技术设计阶段通过上述验证细化，但不得破坏三层职责、证据可追溯、用户可配置留存及第二层活动分段/连续性推断要求。
